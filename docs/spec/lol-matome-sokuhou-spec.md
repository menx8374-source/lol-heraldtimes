# LoL まとめ速報サイト自動運営システム 製品仕様書

## 概要
League of Legends（LoL）の情報を扱う日本語の「まとめ速報」型ゲーム情報サイトと、その記事の収集・生成・掲載・定期更新までを人手なしで回す自動運営システム。Reddit（r/leagueoflegends 等）や 5ch（5ちゃんねる）のスレッド反応をまとめた記事を主軸に、Riot 公式のパッチノート・大会結果・公式ニュース等の一次情報も記事化し、扇情的（好奇心ギャップ型）なまとめ速報タイトルで多数掲載してディスプレイ広告で収益化する。想定利用者は「LoL の最新の話題・掲示板の反応・パッチ情報を日本語でまとめて追いたいプレイヤー／ファン」で、閲覧は無料。運営者はサイトを立ち上げた後、日々の記事投稿を自動運営システムに任せることを目的とする。

## 対象プラットフォーム
`web`（閲覧者向けの公開サイト＋自動運営のバックエンド／バッチ処理）。参考サイトがいずれも PC・スマホのブラウザで読む日本語まとめサイトであり、SEO とディスプレイ広告で収益化するためオープンな Web が必須。ネイティブアプリではなく Web を選定する。閲覧画面はスマートフォン・PC 双方のブラウザで崩れず読めるレスポンシブ表示を前提とする。

## ターゲットユーザー
- LoL をプレイしており、最新パッチ・メタ・大会結果・公式発表を日本語で手早くキャッチアップしたいプレイヤー。
- 掲示板（5ch）や Reddit の「盛り上がっている話題・反応」を、自分で英語スレッドを読まずにまとめで追いたいファン。
- 特定チャンピオンやプロシーン、eスポーツ大会（LJL・Worlds 等）の話題を追いかけるライト〜コア層。
- （運営者側の副次ユーザー）サイトを立ち上げ、日々の記事投稿を自動化して不労収入源にしたい個人運営者。

## スコープ外（Non-Goals）
- 実際の公開ホスティング／独自ドメインへの最終デプロイ接続・DNS 設定・SSL 証明書の手配（アカウントが揃い次第、人手で一度だけ接続する前提。システムは「デプロイ可能な成果物を生成する」ところまでを担う）。
- Google AdSense の審査申請・広告アカウント開設そのもの（人手の一度きりセットアップ。システムは広告タグを差し込める枠と、差し込む広告コードを設定で受け取る仕組みまでを担う）。
- ユーザー登録・ログイン・コメント投稿・会員機能・課金（このバージョンの閲覧サイトは読み取り専用の公開サイト）。
- LoL のリアルタイム戦績トラッカー・ランク照会・試合中オーバーレイ等のゲームデータ連携ツール（まとめ記事サイトであり戦績サービスではない）。
- 英語・その他多言語版サイトの同時運営（日本語版のみ）。
- 記事の完全な事実正確性の保証・専門編集者による校閲（自動運営のため、後述の安全フィルタと出典明記による最低限の緩和にとどめる）。
- ネイティブ広告・アフィリエイト商品リンク・有料会員向けプレミアム記事（主軸はディスプレイ広告のみ）。

## リスク・留意事項
このプロダクトは外部プラットフォームのコンテンツ収集・AI 生成・広告収益化を伴うため、以下のリスクを「何を作るか」の一部として無視できない。実装方法ではなく、仕様として満たすべき制約・緩和策を示す。

- **掲示板・SNS からの収集・転載に関わる著作権／利用規約**: Reddit・5ch の投稿には投稿者・各サービスの権利がある。丸ごと転載は著作権侵害・規約違反になり得る。よって本システムは（a）原文の逐語コピーではなく AI による要約・再構成を基本とし、（b）引用する場合は主従関係（自サイトの記事本文が主、引用が従）を保った短い引用にとどめ、（c）各記事に必ず出典（元スレッド／投稿へのリンク・サービス名）を明記する。Reddit は API 利用規約・レート制限・データ利用ポリシーがあり、5ch も転載・スクレイピングに関する規約（過去に転載禁止の経緯あり）がある。収集はこれら規約・レート制限の範囲で行い、規約で明示的に禁止された取得方法を用いない設計とする。特定個人を誹謗中傷する投稿・晒し投稿はまとめ対象から除外する。
- **Google AdSense の自動生成・コピーコンテンツポリシー**: AdSense は「価値の低い自動生成コンテンツ」「独自性のない複製コンテンツ」を掲載するサイトの収益化を認めず、違反はアカウント停止に直結する。よって生成記事は元ソースの単なる複製ではなく、日本語での要約・再構成・独自の見出し／導入／まとめ・複数ソースの統合など「付加価値」を備える必要がある。無内容な水増し・自動生成の羅列と見なされないための品質基準を受け入れ基準に落とし込む。無限スクロール等でのポリシー違反となる広告配置（コンテンツと誤認させる配置・クリックを誘導する配置）はしない。
- **Riot Games の API／公式コンテンツ利用規約**: Riot の API・公式情報・ゲーム内アセット（チャンピオン画像・ロゴ等）には利用規約と Legal Jibber Jabber ポリシーがある。公式画像・ロゴの無断利用や、Riot 公認と誤認させる表記はしない。サイトに「本サイトは Riot Games が承認・関与するものではない」旨の非公認ディスクレーマーを掲載する。API を使う場合は Riot の利用規約・レート制限を順守する。
- **完全自動運営に伴う無審査公開リスク**: 人手のチェックなしに記事が公開されるため、誤情報・不適切表現（差別・誹謗中傷・過度な暴言・センシティブ話題）・虚偽の速報がそのまま出る危険がある。緩和策として、公開前に通す自動安全フィルタ（NGワード・ヘイト／個人攻撃検出・出典欠落チェック・重複チェック・明らかな未確定情報への「未確認」ラベル付与）を必須機能とし、フィルタを通過しない記事は自動的に非公開（保留キュー）にする。全記事に AI 生成である旨・情報は変動し得る旨の注記を付す。

## 機能一覧

### F1. 閲覧サイトの土台（トップ記事一覧・個別記事ページ）
- 説明: 閲覧者が、トップページで新着まとめ記事の一覧（サムネイル・煽りタイトル・カテゴリ・投稿日時）を見て、クリックすると個別記事ページで本文・出典リンク・投稿日時を読める。参考サイトに倣ったまとめ速報型のレイアウト（記事カードが縦に多数並ぶ一覧＋個別記事）。
- 優先度: Must
- 受け入れ基準:
  - [ ] トップページに記事カードが新しい順（投稿日時降順）で最低10件並び、各カードにタイトル・カテゴリ名・投稿日時・サムネイル領域が表示される。
  - [ ] 記事カードのタイトルをクリックすると、その記事の個別ページに遷移する。
  - [ ] 個別記事ページに、タイトル・本文（見出し＋段落構造）・投稿日時・カテゴリ・出典リンク（1件以上）・「AI により自動生成された記事です」の注記が表示される。
  - [ ] スマートフォン幅（横 375px 相当）と PC 幅（横 1280px 相当）の両方で、レイアウトが崩れず（横スクロールが発生せず）記事が読める。
  - [ ] 存在しない記事 URL にアクセスすると 404 相当のページが表示され、トップへ戻る導線がある。

### F2. カテゴリ・タグ・グローバルナビゲーション
- 説明: 記事が「パッチ／メタ・攻略」「掲示板の反応（5ch）」「海外の反応（Reddit）」「eスポーツ・大会」「公式ニュース」等のカテゴリと、チャンピオン名等のタグで分類され、閲覧者はナビゲーションやタグから同カテゴリ／同タグの記事一覧に辿れる。
- 優先度: Must
- 受け入れ基準:
  - [ ] サイト共通のヘッダーに主要カテゴリへのナビゲーションリンクが並び、どのページからもクリックで各カテゴリ一覧へ遷移できる。
  - [ ] カテゴリ一覧ページで、そのカテゴリに属する記事だけが新しい順に一覧表示される。
  - [ ] 個別記事に付いたタグ（例: チャンピオン名）をクリックすると、同じタグを持つ記事の一覧が表示される。
  - [ ] カテゴリ／タグに属する記事が0件のとき「記事がありません」の空状態が表示され、エラーにならない。

### F3. 人気記事ランキング・サイドバー・関連記事
- 説明: 参考サイトに倣い、サイドバー（PC）または記事下（スマホ）に「人気記事ランキング」「最新記事」等のウィジェットを表示し、個別記事末尾に関連記事（同カテゴリ／同タグ）を出して回遊を促す。
- 優先度: Should
- 受け入れ基準:
  - [ ] サイドバー（またはスマホ時の相当領域）に「人気記事ランキング」ウィジェットが表示され、閲覧数（またはランキング指標）の多い順に最低5件が順位付きで並ぶ。
  - [ ] ランキングの各項目はクリックで該当記事へ遷移する。
  - [ ] 個別記事ページの末尾に、同カテゴリまたは同タグの関連記事が最低3件表示され、クリックで遷移できる（自分自身は関連記事に含まれない）。
  - [ ] 記事の閲覧が発生するとその記事の閲覧数指標が増加し、ランキングに反映される（同一記事を複数回開くとランキング上位に移動することを確認できる）。

### F4. サイト内検索
- 説明: 閲覧者がキーワード（チャンピオン名・話題語など）で記事を検索し、タイトル・本文に一致する記事の一覧を得られる。
- 優先度: Should
- 受け入れ基準:
  - [ ] ヘッダー等に検索ボックスがあり、キーワードを入力して実行すると一致記事の一覧が表示される。
  - [ ] タイトルに含まれるキーワード、本文に含まれるキーワードの双方で記事がヒットする。
  - [ ] 一致0件のとき「該当する記事が見つかりませんでした」の空状態が表示される。
  - [ ] 日本語キーワード（例: チャンピオン名カタカナ）で検索して該当記事がヒットする。

### F5. ソース収集パイプライン（Reddit／5ch／Riot 公式）
- 説明: システムが Reddit（r/leagueoflegends 等）のスレッド、5ch の LoL 関連スレッド、Riot 公式のパッチノート／ニュース等から、記事の素材（タイトル・本文抜粋・URL・投稿日時・反応の抜粋等）を定期的に収集し、共通フォーマットの「収集アイテム」として蓄える。規約・レート制限を順守し、禁止された取得方法は用いない。
- 優先度: Must
- 受け入れ基準:
  - [ ] 収集を実行すると、Reddit ソース・5ch ソース・Riot 公式ソースそれぞれから収集アイテムが取り込まれ、ソース種別（reddit／5ch／riot）・元URL・原題・取得本文（または反応抜粋）・取得日時を持つ共通フォーマットで保存される。
  - [ ] 各収集アイテムに必ず元URL（出典）が保持され、出典欠落のアイテムは保存されない。
  - [ ] 収集はソースごとの取得件数上限・実行間隔（レート制限）を設定で持ち、その範囲を超える取得をしない（設定した上限を超えて連続取得しないことを確認できる）。
  - [ ] 収集対象は LoL 関連に限定するフィルタ（サブレディット指定・スレッドタイトルのキーワード等）を持ち、無関係アイテムが混入しない。
  - [ ] 収集元が一時的に応答しない／取得失敗しても、他ソースの収集は継続され、失敗は記録される（1ソースの失敗で全体が止まらない）。

### F6. 重複排除・正規化
- 説明: 同一の話題・同一ソースを重複して記事化しないよう、収集アイテム間および既存記事との重複を検出し、正規化（表記ゆれ・URL 正規化）した上で「未記事化キュー」に積む。
- 優先度: Must
- 受け入れ基準:
  - [ ] 同一 URL（正規化後）の収集アイテムを2回取り込んでも、記事化候補としては1件にまとめられる（重複が二重に記事化されない）。
  - [ ] タイトル・本文が高い類似度を持つ別 URL のアイテム同士を「同一話題の重複」として検出し、片方のみを記事化候補にする。
  - [ ] 既に記事化済みのソースは再度記事化候補にならない（同じスレッドから二重記事が生成されない）。
  - [ ] 重複排除の結果、記事化候補キューには一意な話題だけが残ることを、重複を含む入力セットで確認できる。

### F7. AI まとめ記事生成
- 説明: 記事化候補の収集アイテムを入力に、AI が日本語のまとめ記事本文（導入→反応／情報の要約・再構成→まとめ）を生成する。掲示板／Reddit のまとめは「反応をまとめた」構成、公式情報は速報記事構成にする。単なる複製ではなく要約・再構成・複数ソース統合で付加価値を持たせ、出典を明記する。
- 優先度: Must
- 受け入れ基準:
  - [ ] 記事化候補を入力すると、見出し・段落を持つ構造化された日本語のまとめ記事本文が生成される（1記事あたり本文が最低300文字以上）。
  - [ ] 生成本文は元ソースの逐語コピーではなく再構成されている（元本文と生成本文の逐語一致率が高すぎない＝定めた閾値以下であることを確認できる）。
  - [ ] 掲示板／Reddit 由来の記事は「複数の反応（コメント）を要約して並べる」構成、Riot 公式由来の記事は「事実の速報＋要点整理」構成で生成される。
  - [ ] 生成記事には出典（元スレッド／投稿／公式ページへのリンク）が本文または末尾に必ず含まれる。
  - [ ] 引用を含む場合、引用部分が記事全体に占める割合が過大でない（自サイト生成文が主・引用が従の主従関係を満たすことを確認できる）。
  - [ ] 生成に失敗した候補は「生成失敗」として記録され、他候補の生成は継続する。

### F8. 煽り速報タイトル生成（中核差別化機能）
- 説明: 「Overwatch攻略まとめ速報@おばにゅー」等に見られる、好奇心ギャップ・感情喚起型のまとめ速報タイトルを再現生成する。冒頭に【】ラベル（【速報】【悲報】【朗報】【朗報か？】【議論】【海外の反応】等）、具体要素（チャンピオン名・数字・パッチ番号・大会名等）、感情フックの語尾（「〜だった件」「〜がヤバい」「〜、判明」「〜で大荒れ」等）を含む、クリックを誘うタイトルにする。
- 優先度: Must
- 受け入れ基準:
  - [ ] 記事本文（または記事化候補）を入力すると、まとめ速報型のタイトル文字列が1本生成される。
  - [ ] 生成タイトルは冒頭に【】で囲んだラベル（あらかじめ定義したラベル語彙のいずれか）を1つ含む。
  - [ ] 生成タイトルは、記事内容に実在する具体要素（チャンピオン名・数値・パッチ番号・大会名・固有名詞のいずれか）を最低1つ含む（本文に存在しない固有名詞を捏造しない）。
  - [ ] 生成タイトルは、定義済みの感情フック（好奇心ギャップ／驚き／煽りの語尾・言い回し）パターンのいずれかに合致する。
  - [ ] 生成タイトルの文字数が定めた範囲（例: 全角20〜48文字相当）に収まる。
  - [ ] タイトル品質を自動採点するチェッカーがあり、上記4点（ラベル／具体要素／感情フック／文字数）を判定して合格・不合格を出せる。10件のサンプル記事に対して合格率が90%以上になる。
  - [ ] 同一記事に対して生成しても、ラベルや語尾のバリエーションが偏りすぎない（複数記事で全部同じラベル・同じ語尾に固定化されないことを確認できる）。
  - [ ] 差別的・過度に攻撃的な表現、実在個人を中傷する表現を含むタイトルは生成されない（安全フィルタ済み語彙で構成される）。

### F9. コンテンツ安全フィルタ・モデレーション
- 説明: 公開前に全記事（本文＋タイトル）を自動フィルタに通し、NGワード・ヘイト／個人攻撃・出典欠落・重複・明らかな未確定情報を検出。通過しないものは自動的に非公開（保留キュー）にし、公開されない。未確定情報には「未確認」ラベルを付す。
- 優先度: Must
- 受け入れ基準:
  - [ ] 記事は「安全フィルタ通過」状態にならない限り公開されない（公開記事は必ずフィルタ通過済み）。
  - [ ] NGワード（差別語・過度な暴言等の定義済みリスト）を含む記事は保留となり公開されない。
  - [ ] 出典リンクを持たない記事は保留となり公開されない。
  - [ ] 特定個人を名指しで中傷／晒す内容と判定された記事は保留となり公開されない。
  - [ ] 保留になった記事は理由（NGワード／出典欠落／重複／中傷等）とともに保留キューに記録され、公開キューには入らない。
  - [ ] 未確定・噂レベルと判定された情報には記事に「未確認」ラベルが付与された上で公開される（もしくは保留される）。

### F10. 自動公開・スケジューリング・継続運営
- 説明: 収集→重複排除→記事生成→タイトル生成→安全フィルタ→公開までの一連の流れを、定期スケジュール（例: 数時間おき）で人手なしに繰り返す。1回の実行で決めた本数を公開し、公開時刻を分散させる等、まとめサイトとして自然な更新頻度で回す。
- 優先度: Must
- 受け入れ基準:
  - [ ] スケジュール実行を1回起動すると、収集→重複排除→生成→タイトル→安全フィルタ→公開まで人手介入なしで完走し、新しい公開記事が0件より多く増える。
  - [ ] 1回の実行で公開する記事本数の上限を設定でき、その本数を超えて一度に公開しない。
  - [ ] スケジュール設定（実行間隔）を持ち、設定に従って繰り返し実行できる（少なくとも、繰り返し起動を模擬したときに毎回新規記事が積み上がる）。
  - [ ] 同じ実行を続けても既公開記事が重複公開されない（F6 の重複排除が公開段階でも効く）。
  - [ ] 記事化候補が枯渇しているときは、エラーにならず「今回は新規公開なし」で正常終了する。

### F11. エラー耐性・自動リカバリ・運営ログ
- 説明: 完全自動運営を止めないため、各工程の失敗を握りつぶさず記録しつつ、1件の失敗で全体を停止させない。失敗した工程は次回実行でリトライされ、実行結果（収集件数・生成件数・公開件数・失敗件数）がログに残る。
- 優先度: Must
- 受け入れ基準:
  - [ ] いずれかの収集ソース・生成・タイトル・フィルタのうち1件が失敗しても、パイプライン全体は停止せず、他の記事の処理を完走する。
  - [ ] 各実行ごとに、収集件数・記事化候補数・生成成功／失敗数・公開数・保留数を含む実行ログが記録される。
  - [ ] 生成やタイトル付けに失敗した候補は破棄されず、次回実行で再処理の対象になる（恒久的に消えない）。
  - [ ] 外部ソースがすべて応答しない最悪ケースでも、パイプラインはクラッシュせずログにエラーを残して正常終了する。

### F12. 広告枠差し込み・収益化配置
- 説明: 参考サイトのマネタイズを踏襲し、記事内（見出し前後）・記事一覧・サイドバー・記事末尾等に広告枠を差し込める。広告コード（AdSense 等のタグ）は設定で受け取り、各枠に反映する。AdSense ポリシーに反する配置（コンテンツ誤認・クリック誘導）はしない。
- 優先度: Must
- 受け入れ基準:
  - [ ] 個別記事ページに、記事上部・本文中（見出し間）・記事末尾・サイドバーの各広告枠が存在し、枠の位置が視認できる（広告コード未設定時はプレースホルダー枠が表示される）。
  - [ ] トップ記事一覧内にも一定間隔で広告枠が差し込まれる。
  - [ ] 広告コードを設定に入れると、その内容が各広告枠に出力される（枠に任意の広告タグ文字列を反映できることを確認できる）。
  - [ ] 広告枠がコンテンツ本文やナビゲーションと誤認される配置になっておらず、記事本文と視覚的に区別できる（枠にラベルまたは区切りがある）。
  - [ ] 広告枠を含んでもスマホ・PC でレイアウトが崩れず、記事本文が読める。

### F13. SEO・構造化データ・サイトマップ・OGP
- 説明: 検索流入とディスプレイ広告収益のため、各ページに適切なタイトルタグ・メタディスクリプション・OGP（SNS シェア時のカード）・構造化データ（記事情報）を出力し、サイトマップと robots を提供する。
- 優先度: Should
- 受け入れ基準:
  - [ ] 各個別記事ページに、記事タイトルを反映した `<title>`、内容を要約したメタディスクリプション、OGP（og:title／og:description／og:image／og:url）が出力される。
  - [ ] 各個別記事ページに記事の構造化データ（見出し・公開日時・カテゴリ等を含む記事メタ情報）が出力される。
  - [ ] 全公開記事とカテゴリページを列挙したサイトマップが生成され、アクセスできる。
  - [ ] robots 指定が提供され、収集・公開してはならない領域（管理／保留キュー等）がクロール対象から除外される。
  - [ ] トップ・カテゴリ・記事の各ページで `<title>` が固有（ページごとに異なる）である。

### F14. 運営監視ダッシュボード
- 説明: 運営者が、自動運営の稼働状況（直近実行の収集／生成／公開／保留件数、保留キューの中身と保留理由、失敗ログ、公開記事総数、人気記事）を一目で把握できる管理用ダッシュボード。閲覧者向けの公開サイトとは分離する。
- 優先度: Should
- 受け入れ基準:
  - [ ] ダッシュボードに、直近の実行結果（収集件数・生成件数・公開件数・保留件数・失敗件数）が時系列で表示される。
  - [ ] 保留キューの記事が保留理由付きで一覧表示される。
  - [ ] 公開記事の総数と人気記事ランキングが表示される。
  - [ ] エラー／失敗ログが確認でき、どの工程で何が失敗したかが分かる。
  - [ ] ダッシュボードは公開サイトのナビゲーションからは辿れず（一般閲覧者に露出せず）、robots でクロール対象外になっている。

### F15. 出典表記・法務コンプライアンス表示（免責・非公認・オプトアウト）

- 優先度: Must
- 受け入れ基準:
  - [ ] 全公開記事に出典（元ソースへのリンク＋サービス名）が表示される（出典のない記事は F9 により公開されない）。
  - [ ] サイトのフッター等に「本サイトは Riot Games が承認・関与するものではない」旨の非公認ディスクレーマーが常時表示される。
  - [ ] 全公開記事に「AI により自動生成された記事であり、情報は変動し得る」旨の注記が表示される。
  - [ ] 免責事項・プライバシー方針・掲載削除依頼（オプトアウト）の連絡導線を持つ固定ページが存在し、フッターから到達できる。
  - [ ] 引用部分と自サイト生成文が視覚的に区別できる（引用は引用として明示される）。

## 用語集
- **まとめ速報型記事**: 掲示板／SNS のスレッド・反応や公式情報を、日本語で要約・再構成し、扇情的なタイトルで多数掲載するゲーム情報サイトの記事形式。参考: 「Overwatch攻略まとめ速報@おばにゅー」等。
- **煽り／好奇心ギャップ型タイトル**: 冒頭の【】ラベル・具体要素・感情フックの語尾で構成され、続きを読みたくさせるクリック誘導型のタイトル。本仕様の中核差別化要素（F8）。
- **収集アイテム**: 各ソースから取り込んだ記事素材の共通フォーマット単位（ソース種別・元URL・原題・本文／反応抜粋・取得日時）。
- **記事化候補キュー**: 重複排除後、まだ記事化していない一意な話題の待ち行列。
- **保留キュー**: 安全フィルタを通過せず公開されなかった記事と、その保留理由を溜める場所。
- **完全自動運営**: 収集→重複排除→記事生成→タイトル生成→安全フィルタ→公開までを人手なしで定期実行する運用（初回のアカウント登録・ドメイン設定等の一度きりセットアップは人手を許容）。
