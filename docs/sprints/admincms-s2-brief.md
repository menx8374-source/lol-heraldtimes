# admincms-S2 — 指定URLからの手動記事化（Reddit / X）

仕様書 `docs/spec/admin-cms-v2-spec.md` の **Sprint 2**（F5, F6）を実装する。運営者がX投稿URL・RedditスレッドURLを貼ると、Hotness（盛り上がり判定）を無視して**要レビュー状態の下書き記事**を生成する。5chは対象外。

## 前提（S1で実装済み・利用する）
- `Article.status="review"`（要レビュー）・レビューキュー・プレビュー(`/admin/articles/[id]/preview`)・承認/却下。手動記事化の出力先は**常に要レビュー(review)**（カテゴリポリシーに関わらず。手動は必ず運営確認を挟む）。
- 既存の収集アダプタ（`src/lib/collection/adapters/x.ts`＝GetXAPI, `reddit.ts`＝Arctic Shift）・記事生成(`generateArticleForCandidate`)・タイトル生成・安全フィルタ(`moderateArticleContent`)・カテゴリ判定。

## 含まれる機能（F5, F6・要点）
- **F5 Reddit スレッドURL→下書き**: `https://www.reddit.com/r/<sub>/comments/<id>/<slug>/` を取得→要レビュー下書き。カテゴリ=「海外の反応」。本文=元投稿＋コメント由来レス。出典=元スレURL。
- **F6 X 投稿URL→下書き**: `https://x.com/<user>/status/<id>` を取得（返信/引用含む）→要レビュー下書き。カテゴリ=「Xの反応」。X_API_KEY未設定なら実行前に明示して弾く。

## 受け入れ基準（仕様書 Sprint 2 原文）
- [ ] `/admin` に「指定 URL から記事化」パネルがあり、URL 入力欄と実行ボタン、対応 URL 形式の説明（X 投稿 URL / Reddit スレッド URL、5ch は対象外）が表示される。
- [ ] Reddit スレッド URL（`https://www.reddit.com/r/leagueoflegends/comments/<id>/<slug>/`）を入力して実行すると、実行中である旨が表示され、完了後に「記事を作成しました」という結果とその記事の「プレビュー」「編集」への導線が表示される。
- [ ] 上記で作成された記事はレビューキューに現れ、公開サイトのトップ一覧・検索結果には現れない。
- [ ] 上記記事のプレビューを開くと、カテゴリが「海外の反応」、本文に元スレッド情報のブロックとコメント由来のレスブロックが含まれ、出典として元スレッド URL が表示される。
- [ ] `https://old.reddit.com/r/.../comments/<id>/<slug>`（末尾スラッシュ無し）、`...?utm_source=share&utm_medium=web` 付きの URL を入力しても、同じスレッドとして取得され記事が作成される。
- [ ] スコアもコメント数も小さい（自動収集では記事化されない水準の）スレッド URL を入力しても、盛り上がり判定で弾かれずに記事が作成される。
- [ ] X 投稿 URL（`https://x.com/<user>/status/<id>`）を入力して実行すると、記事が作成され、プレビューでカテゴリが「Xの反応」、本文に元ポスト情報と返信／引用由来のレスブロックが含まれ、出典として元ポスト URL が表示される。
- [ ] `https://twitter.com/<user>/status/<id>?s=20` 形式の URL でも同じ投稿として取得され記事が作成される。
- [ ] 返信が1件も取得できない X 投稿でも、元ポスト単体の記事として下書きが作成され、本文が空にならない。
- [ ] X の API 資格情報が未設定の環境で X の URL を実行すると、「X の API キーが未設定のため利用できません」に相当するメッセージが表示され、記事は作成されず、同じ画面で Reddit の URL からの記事化は正常に成功する。
- [ ] 対応しないホスト（`https://example.com/foo`）を入力して実行すると「この URL 形式には対応していません」と表示され、レビューキューの件数が増えない。
- [ ] 空文字・URL でない文字列（`abc`）を入力して実行すると入力エラーが表示され、記事が作成されない。
- [ ] 存在しない／削除済みの Reddit スレッド URL、削除済みの X 投稿 URL を入力すると、その旨の日本語エラーが表示され、レビューキューに空の記事や本文が欠けた記事が増えない。
- [ ] レート制限・認証エラーで取得に失敗した場合、原因が分かる日本語メッセージが表示され、記事が作成されない。
- [ ] 既に記事化済みの URL を再度入力して実行すると、二重に記事が作られず「この URL は記事化済みです」と既存記事への導線が表示される（レビューキューの件数が増えない）。
- [ ] 実行ボタンを連打しても記事が二重に作成されない（実行中はボタンが無効化される等）。
- [ ] 手動記事化で作られた記事も安全フィルタを通っており、NG ワードを含むスレッドを記事化した場合は公開されず、既存の保留キューに理由付きで入る。
- [ ] 手動記事化を実行しても、既存の自動収集パイプラインの動作・実行ログが壊れない（実行後にパイプラインを1回回して従来どおり完走する）。

## テスト観点（自動テストを書く対象・原文）
- URL 判定と正規化: 対応ホスト（reddit.com / old.reddit.com / www.reddit.com / x.com / twitter.com）と非対応ホスト、クエリ付き・末尾スラッシュ有無・大文字小文字違い、投稿 ID の抽出結果が同一 URL バリエーションで一致すること、非 URL 文字列や `javascript:` 等の危険スキームを拒否すること。
- 記事化済み判定: 同じ正規化結果の URL を2回投入したときに2件目が作成されず既存記事を返すこと。
- 失敗時の扱い: 取得失敗（404／削除済／認証エラー／レート制限）で記事が作成されないこと、資格情報未設定時に X 経路が実行前に拒否されること。
- 盛り上がり判定の迂回: 判定を満たさない入力でも記事化経路が最後まで進むこと（自動収集経路の判定挙動は変わらないこと）。

- 致命的バグ: 0件 ／ コンソールエラー: 0件 ／ 上記受け入れ基準の充足率: 100% ／ テストスイート全体が Green

## 実装ガイド（既存コード結線・オーケストレーターより）
- **URLパース純関数** `src/lib/admin/manual-article-url.ts` 等を新設: 入力URL→`{ source: "reddit"|"x", externalId, normalizedUrl } | { error: "unsupported"|"invalid" }`。
  - ホストのホワイトリスト: reddit=`reddit.com`/`www.reddit.com`/`old.reddit.com`、x=`x.com`/`twitter.com`/`www.x.com`/`mobile.twitter.com`。それ以外・`javascript:`等の非http(s)スキーム・非URL文字列は拒否。
  - Reddit: `/comments/<id>/` からthread id抽出。X: `/status/<id>` からtweet id抽出。クエリ/末尾スラッシュ/大文字小文字は正規化して**同一入力バリエーションが同一externalIdに落ちる**こと。
- **単発取得**: 既存アダプタのGetXAPI(`x.ts`)/Arctic Shift(`reddit.ts`)を再利用し、指定id 1件＋その会話（Xは返信/引用=既存fetchTopReplies相当、Redditはコメント）を取得。取得は指定1件の範囲に限定（無制限クロールしない）。失敗（404/削除/認証/レート制限）は例外を握り**記事を作らず**日本語メッセージを返す。
- **生成→保存**: 取得結果を既存の`Post`/candidate形に組み立て、`generateArticleForCandidate`で生成。**Hotness評価は通さない**（手動=強制）。安全フィルタ(`moderateArticleContent`)は通す→NGなら`status="held"`(理由付き・保留キュー)、通れば**`status="review"`**（手動は常に要レビュー・カテゴリポリシー参照しない）。カテゴリはソース既定（reddit→海外の反応 / x→Xの反応）。
- **二重防止**: `Post.@@unique([sourceType, externalId])` と `Article.postId @unique` を活用。既に同externalIdのPost/記事があれば新規作成せず既存記事への導線を返す（「記事化済み」）。
- **UI**: `src/app/admin/page.tsx` に「指定URLから記事化」パネル（server action）。実行中表示・二重送信防止（`useFormStatus`/disabled）。結果（成功時はプレビュー/編集リンク・失敗時は日本語理由）を表示。X_API_KEY未設定時はX URLを実行前に弾いて明示（Reddit経路は動く）。
- **秘密**: X_API_KEYは`.env`から読む（ハードコード禁止・`.env.example`にキー名のみ）。

## 制約・非目標
- 5chの手動記事化は対象外。Hotnessロジック・生成品質・自動収集経路の挙動は変更しない。公開サイトの見た目は変えない。
- S1で確立した「要レビュー記事が公開側に一切出ない不変条件」を壊さない（手動記事化物も review で作られ公開側に出ない）。
- 新規依存は最小限。テスト必須（上記テスト観点、特にURLパース純関数・二重防止・失敗時非作成）。スキーマ変更は避ける（既存Post/Articleで足りるはず）。
