# admincms-S3 — フル構造エディタ基盤＋反応系ブロックの編集

仕様書 `docs/spec/admin-cms-v2-spec.md` の **Sprint 3**（F7, F8）を実装する。既存の生JSON textarea編集画面(`/admin/articles/[id]/edit`)を、**ブロックをカードで並べて編集する構造化エディタ**に置き換える。ブロックの追加/削除/並べ替え＋メタ編集＋反応系ブロックのフィールド編集。

## 前提（S1/S2で実装済み・利用する）
- `Article.status="review"`・レビューキュー・プレビュー(`/admin/articles/[id]/preview`)・承認/却下。
- 現状の編集: `src/app/admin/articles/[id]/edit/page.tsx`（タイトル＋本文生JSON textarea）＋`updateArticleAction`/`updateArticleContent`（`src/lib/admin/articles-admin.ts`）。**本スプリントでこの編集画面を構造化エディタに置換する。**
- 本文検証: `src/lib/article-body.ts` の `parseArticleBody`（不正は `InvalidArticleBodyError`）。保存時は必ずこれを通す。ブロック型・検証規則は**変更しない**（下記参照）。

## 対象ブロック型（本スプリント=反応系＋共通。パッチ系[patchChange/toc/linkButton]はS4）
`article-body.ts` の型に厳密に従う:
- **reaction**: `number`(正整数), `name`(非空), `lines`(1件以上・各`{text非空, emphasis?:"red"|"orange", original?}`), `anchors?`(正整数配列・同一記事内に存在する番号のみ), `emphasis?`(bool), `emphasisColor?`("red"|"blue"|"purple"|"orange")
- **redditSource**: `title`(非空), `author?`, `subreddit?`, `url`(https の reddit.com のみ=`isRedditSourceUrl`)
- **heading**: `text`(非空), `anchor?`（S4の目次連携で使うが編集欄自体は用意してよい）
- **paragraph**: `text`(非空)
- **quote**: `text`(非空), `source?`
- **embed**: `provider`(`isEmbedProvider`), `url`(`isAllowedEmbedUrl(provider,url)`でホワイトリスト), `caption?`
- **image**: `url`(`isSafeImageUrl`＝ローカル/data:image/https), `alt`(非空), `credit?`

## 含まれる機能（F7, F8・要点）
- **F7 エディタ基盤**: 各本文ブロックを種別ラベル付きカードで縦に並べる。↑↓で並べ替え・削除・「ブロックを追加」で種別選択して任意位置(末尾/指定ブロック直後)に挿入。タイトル・要約(metaDescription)・カテゴリ(既存から選択)・タグ(複数・追加/削除)・サムネURL・公開状態(要レビュー/公開)を同画面で編集して保存。保存時 `parseArticleBody` で検証し不正なら**どのブロックのどのフィールドが不正か**を表示して保存しない。生JSON textareaは廃止。
- **F8 反応系フィールド編集**: 上記reaction/redditSource/heading/paragraph/quote/embed/imageの各フィールドを種別に適した入力欄で編集。レスは番号・名前・本文行(追加/削除)・行単位強調(なし/赤/オレンジ)・レス単位強調(オン/オフ＋色)・アンカー編集。存在しないアンカー番号・reddit以外のURL・ホワイトリスト外embed URLは保存拒否。

## 受け入れ基準（仕様書 Sprint 3 原文）
- [ ] レビューキューまたは記事管理から反応記事（カテゴリ「5chの反応」「海外の反応」「Xの反応」のいずれか）の「編集」を開くと、本文の各ブロックが種別ラベル（レス／見出し／段落／引用／埋め込み／画像／Redditソース）付きのカードとして上から順に並び、生の JSON テキストエリアが画面のどこにも表示されない。
- [ ] 編集画面の上部に、タイトル・要約（メタディスクリプション）・カテゴリ（既存カテゴリからの選択）・タグ（複数、追加と削除）・サムネイル URL・公開状態（要レビュー／公開）の編集欄がある。
- [ ] タイトルを変更して保存し、編集画面を開き直すと変更後のタイトルが表示され、プレビューにも反映されている。
- [ ] タグを1つ追加して保存し、開き直すと追加したタグが残っており、既存のタグが失われていない。
- [ ] 3番目のブロックの「↑」を押して2番目と入れ替えて保存し、開き直すと入れ替えた順序が保持され、プレビューでも同じ順序で表示される。
- [ ] 任意のブロックの「削除」を押して保存すると、そのブロックが編集画面からもプレビューからも消える。
- [ ] 「ブロックを追加」から「段落」を選び、指定したブロックの直後に挿入して本文を入力し保存すると、その位置に段落が入った状態でプレビューに表示される。
- [ ] 「ブロックを追加」の選択肢に、反応記事で使う種別（レス／見出し／段落／引用／埋め込み／画像）が並ぶ。
- [ ] レス（reaction）ブロックのカードで、レス番号・名前・本文行（1行ずつの入力欄）を編集して保存すると、プレビューに「番号: 名前」と編集後の各行が表示される。
- [ ] レスの「行を追加」で行を増やし、内容を入力して保存すると、プレビューにその行が増えている。逆に「行を削除」で行を減らして保存すると、その行が消えている。
- [ ] レスのある行の強調を「赤」に設定して保存すると、プレビューでその行だけが赤系の強調表示になり、他の行は通常表示のままである。
- [ ] レス全体の強調をオンにし色を「青」にして保存すると、プレビューでそのレスが大きく強調表示され、他のレスは通常表示のままである。強調をオフに戻して保存すると通常表示に戻る。
- [ ] レスのアンカーに同一記事内に存在するレス番号を指定して保存でき、プレビューでその参照が表示される。存在しない番号を指定して保存しようとすると、どのブロックが不正かが分かるエラーが表示され、記事は変更されない。
- [ ] 海外の反応記事の Reddit ソース引用ブロックで、元スレタイトル・作者・サブレディット・元スレ URL を編集して保存でき、プレビューに反映される。URL に reddit 以外のホスト（`https://example.com/x`）を入れて保存しようとするとエラーが表示され、記事は変更されない。
- [ ] 埋め込み（embed）ブロックで提供元・URL・キャプションを編集して保存でき、プレビューに埋め込みカードとして表示される。ホワイトリスト外の URL を入れて保存しようとするとエラーが表示され、記事は変更されない。
- [ ] 見出し・段落・引用ブロックのテキスト（引用は出典表記も）を編集して保存すると、プレビューに反映される。
- [ ] 本文のブロックをすべて削除して保存しようとすると保存が拒否され、「本文は1件以上のブロックが必要です」に相当するエラーが表示され、記事は変更されない。
- [ ] レスの本文行を空にして保存しようとすると保存が拒否され、どのブロックのどのフィールドが不正かが分かるメッセージが表示され、入力中の他の編集内容が画面から失われない。
- [ ] 「キャンセル」を押すと編集が破棄されて一覧に戻り、破棄した内容が記事に反映されていない。
- [ ] 編集画面から「プレビュー」へ遷移でき、保存済みの内容がプレビューに反映されている。
- [ ] 編集画面で公開状態を「公開」に変更して保存すると、その記事がレビューキューから消え、公開サイトのトップ一覧に現れる。
- [ ] 既存の記事（本追加の前から存在する公開記事）を編集画面で開いても、本文ブロックがすべて欠落せずにカードとして表示され、何も変更せずに保存しても内容が変化しない。
- [ ] 横 1280px の画面幅で編集画面のレイアウトが崩れず、すべての操作ボタンが操作できる。

## テスト観点（自動テストを書く対象・原文）
- フォーム入力→ブロック配列への変換: 各反応系ブロック種別について、入力値から組み立てた構造が既存の本文検証を通ること。行の追加・削除・並べ替え・挿入位置指定の結果が期待した順序になること。
- 検証エラーの伝播: 不正入力（空行・存在しないアンカー・非 reddit の URL・ホワイトリスト外の埋め込み URL・ブロック0件）で保存が拒否され、どのブロック・どのフィールドが原因かを含むエラーが返ること。
- 往復の同一性: 既存記事を読み込んでフォームに展開し、何も変更せず保存したときに本文が元と同一になること（情報が落ちないこと）。
- メタフィールド更新: タイトル・要約・カテゴリ・タグ・サムネイル・公開状態の更新が独立に反映され、他フィールドを巻き込まないこと。

## 実装ガイド（既存コード結線・オーケストレーターより）
- **フォーム⇔ブロックの変換純関数**（新設 例 `src/lib/admin/article-editor-form.ts`）: エディタの入力状態(シリアライズされたform値)↔`ArticleBodyBlock[]` の相互変換。保存側は組み立てた配列を必ず `parseArticleBody` に通し、`InvalidArticleBodyError.message`（既に「本文ブロック[i]の…」の粒度）をそのままUIに返す。**この変換とアンカー整合(存在番号のみ)を純関数化しユニットテストの主対象にする**（UIはClient Component）。
- **アンカー検証**: reactionの`anchors`が「同一記事内に存在するreaction番号」であることは `parseArticleBody` 単体では担保されない（各ブロック単位検証のため）。保存前に**記事全体を見た整合チェック**（存在しない番号→拒否・どのブロックか明示）を追加する純関数を用意（S4のtoc anchor↔heading anchorと同型の全体検証。ここで土台を作ると再利用できる）。
- **編集画面**: `src/app/admin/articles/[id]/edit/page.tsx` を、ブロックカードUIのClient Component（例 `ArticleEditor.tsx`）＋server action保存に置き換える。生JSON textareaは撤去。カードは種別ラベル・↑↓・削除・「直後に追加」。メタ(タイトル/要約/カテゴリselect/タグ/サムネ/公開状態)を上部に。既存記事を開いた時点でブロックがカードに展開される（往復同一性）。
- **保存アクション**: `updateArticleContent`(articles-admin.ts) を拡張し、title/metaDescription/category/tags/thumbnailUrl/status＋body(ブロック配列) を受け取る。検証(parseArticleBody＋アンカー整合)→NGはthrowでUIにメッセージ＆記事不変。公開状態変更(review⇄published)を反映。**公開中記事の編集で不合格になったら保留(held)へ落とす既存の安全不変条件は維持**（moderate再チェックの既存挙動を壊さない）。tagsは既存の connectOrCreate パターンで置換更新（追加/削除が反映され既存タグを失わない）。
- **プレビュー整合**: 保存後、既存プレビュー(`/admin/articles/[id]/preview`)・公開ページの `ArticleBodyView` で正しく描画される（表示は既存コンポーネント再利用・変更しない）。
- **往復同一性の要**: フォーム展開→無編集保存で `body` が元と一致すること（`original`併記・emphasis・emphasisColor・anchors等の任意フィールドを落とさない）。ここが最も壊れやすいのでテスト必須。

## 制約・非目標
- パッチ系ブロック（patchChange/toc/linkButton）の編集UIはS4（本S3では反応系＋共通ブロックに集中。ただし基盤=追加/削除/並替/保存/検証はS4で流用するため汎用に作る）。
- ブロック型・`article-body.ts`の検証規則・表示コンポーネント(`ArticleBodyView`等)・公開サイトの見た目は変更しない。S1の「要レビュー記事が公開側に出ない不変条件」を壊さない。
- 新規依存は最小限（リッチテキスト/WYSIWYGライブラリは入れない＝仕様Non-Goals）。テスト必須（フォーム⇔ブロック変換・検証エラー伝播・往復同一性・メタ更新独立性）。
- 横1280pxで崩れないこと（モバイル最適化は非目標）。
