# パッチ刷新S8 — チャンピオン変更・アイテム変更のみに限定＋その他は公式パッチノートへ誘導

パッチ記事で扱う変更内容を、**絶対に正確に抽出できる「チャンピオンの変更」「アイテムの変更」（いずれも数値＋記述式）だけ**に限定する。
システム/アリーナ/バグ修正/ルーン/オーグメント/メイヘム等の**それ以外は本文に載せず、公式パッチノートへ誘導**する。**AI不使用**。対象: Web。

## 背景（なぜ限定するか）
- S1〜S7の検証で、**チャンピオン変更・アイテム変更は誤帰属ゼロ・逐語正確で「絶対の自信」がある**（対象IDをアイコンURLから確定・11パッチ検証済み）。
- 一方、システム/アリーナ/バグ修正/大型パッチ特殊節は「内容は逐語正確だが対象名の粒度が粗い/将来の新形式に未知のリスク」がある。
- ユーザー方針: **当サイトのパッチ記事は「チャンピオン変更・アイテム変更のまとめ」に特化**し、その他は公式で見てもらう。これで正確性を100%担保しつつ、粒度の粗いカードを排除して記事品質を上げる。

## 含まれる機能

### F-S8-1: 本文を champion / item の対象のみに限定（compose.ts）
`composeDetailedPatchBody`（DOM経路）で、`PatchChangeTarget`（S1〜S7の抽出結果）のうち **`targetKind` が `"champion"` または `"item"` の対象だけ**を本文の patchChangeブロックにする。それ以外（`system`/`arena`/`bugfix`/`rune`/`other`）は**本文に出さない**。
- `targetKind` 判定は既存（アイコンURLパス champion/ item/、セクション種別）。champion/item は誤帰属ゼロで確実。
- チャンピオン対象は既存どおり「主な強化/主な弱体化/その他の調整」の3グループへ。**アイテム対象は独立セクション「アイテムの変更」**にまとめる（3分類はしない、または item も強化/弱体で分けるかは既存の扱いを踏襲。まずは「アイテムの変更」章に対象名付きで列挙）。

### F-S8-2: 冒頭サマリ・目次を champion / item のみで再計算
- 冒頭1文サマリ（`buildPatchIntroSummary`）を champion/item の集計に更新: 例「今回のパッチではチャンピオン{N}体（強化{a}・弱体化{b}・調整{c}）とアイテム{M}件の変更をまとめました。システム・アリーナ・バグ修正などその他の変更点は公式パッチノートをご覧ください。」（数値はchampion/itemのみ。0の項目は省略・純テンプレ）。
- 目次(toc)は champion 3グループ＋「アイテムの変更」のみを列挙（除外セクションは目次に出さない）。

### F-S8-3: 「その他の変更点は公式で」誘導セクション
- 本文末尾（アイテム章の後・出典/リンクボタンの近く）に、**除外したことを明示する誘導**を出す（情報を隠すのではなく公式へ案内）:
  - 見出し＋短文: 「システム・アリーナ・バグ修正・ルーン等、チャンピオン/アイテム以外の変更点は公式パッチノートでご確認ください。」
  - **公式リンクボタン**（既存の `linkButton`・S4のLoL意匠「▶ パッチ{番号} 公式パッチノートを読む」）を必ず添える。
- 除外対象が0件（champion/itemしか無いパッチ）でも、公式リンクボタンは従来どおり出す（誘導文は「その他の変更がある場合」を含む自然な文にするか、除外0件なら誘導文を省いてリンクのみでよい）。

## 制約・非目標
- **AIは使わない**（限定・集計・誘導は純ルール/テンプレ）。**逐語維持・捏造禁止**（載せる champion/item は公式逐語のまま）。
- **情報を隠さない**：除外カテゴリは「公式で見てね」と明示＋公式リンクで誘導する（黙って消さない）。
- S1〜S7の抽出ロジック自体は変更しない（抽出は全カテゴリ続行し、**本文化の段階で champion/item に絞る**）。将来「他カテゴリも載せたい」となれば絞りを外すだけで戻せるよう、フィルタは1箇所に集約する。
- direction分類（強化/弱体/調整・曖昧はadjust）・S4のLoLデザイン・アイコン表示・S5速報(opt-in)は不変。fact/summaryモード・非パッチ記事・他ソース・翻訳/SEOは不変。DBスキーマ変更なし・新規依存なし。

## テスト（必須・S1〜S7フィクスチャ流用・実ネット非依存）
1. 26.14で、本文の patchChangeブロックが **champion（アジール/コーキ/ガレン等）と item（不滅の道/プロトプラズム等）のみ**になる。**system（ブルーバフ）・bugfix・arena は本文に出ない**。
2. 冒頭サマリが champion/item の集計になり、「その他は公式で」の文言を含む。目次が champion 3グループ＋アイテムのみ。
3. 誘導セクション＋公式リンクボタン（▶ラベル・LoL意匠）が末尾に出る。
4. 除外対象が0件のパッチでも壊れない（誘導文の出し分け・リンクは出る）。逐語維持（載せる内容は正確）。
5. 既存の compose/parser/article-body-view テストのうち「非champion/item対象の本文表示」を検証していたものは、**S8の新仕様（除外＋誘導）に更新**する。他のテストは回帰しない。

## 受け入れ基準
1. `npx vitest run` 全Green・`npx tsc --noEmit`・`npm run build`・`npm run lint` 通過。
2. パッチ記事本文が**チャンピオン変更・アイテム変更のみ**になり、それ以外は本文に出ず「公式パッチノートで確認」＋公式リンクボタンで誘導される。誤帰属ゼロ・逐語維持・S4デザイン維持。
3. AI不使用・DBスキーマ変更なし・新規依存なし・抽出ロジック(S1〜S7)は不変・絞りは1箇所集約で可逆。

## 評価基準（evaluator向け）
- テスト全Green・build/tsc/lint通過・コンソールエラー0。
- パッチ記事に champion/item の変更のみが正確に出て、system/arena/bugfix等が本文から消え、公式誘導＋リンクボタンが出る。冒頭サマリ・目次も限定。逐語・デザイン維持。
- 受け入れ基準1〜3を満たす。
