# Sprint 3 brief — ソース収集パイプラインと重複排除を構築する

> 仕様書 `docs/spec/lol-matome-sokuhou-spec.md` から Sprint 3 該当部分を原文のまま抜粋。generator/evaluator の主参照先。

## 対象プラットフォーム
`web`（自動運営のバックエンド／バッチ処理を含む）。

## ⚠ このスプリントの実装方針（モック）
**収集（Reddit／5ch／Riot 公式）は本番 API に接続せず、サンプル／固定データ（フィクスチャ）で実装する**（ユーザー決定: 収集はモックで進め後で本接続）。差し替え可能なプロバイダ構造にし、後日 API キー等が揃い次第、収集アダプタを本接続に切り替えられる設計にする。受け入れ基準はサンプル入力で満たせるよう記述されている。evaluator はモック前提で判定してよい（本物の外部サービス連携としては判定しない）。

## 含まれる機能: F5, F6

### F5. ソース収集パイプライン（Reddit／5ch／Riot 公式）
- 説明: システムが Reddit（r/leagueoflegends 等）のスレッド、5ch の LoL 関連スレッド、Riot 公式のパッチノート／ニュース等から、記事の素材（タイトル・本文抜粋・URL・投稿日時・反応の抜粋等）を定期的に収集し、共通フォーマットの「収集アイテム」として蓄える。規約・レート制限を順守し、禁止された取得方法は用いない。
- 優先度: Must
- 受け入れ基準:
  - [ ] 収集を実行すると、Reddit ソース・5ch ソース・Riot 公式ソースそれぞれから収集アイテムが取り込まれ、ソース種別（reddit／5ch／riot）・元URL・原題・取得本文（または反応抜粋）・取得日時を持つ共通フォーマットで保存される。
  - [ ] 各収集アイテムに必ず元URL（出典）が保持され、出典欠落のアイテムは保存されない。
  - [ ] 収集はソースごとの取得件数上限・実行間隔（レート制限）を設定で持ち、その範囲を超える取得をしない（設定した上限を超えて連続取得しないことを確認できる）。
  - [ ] 収集対象は LoL 関連に限定するフィルタ（サブレディット指定・スレッドタイトルのキーワード等）を持ち、無関係アイテムが混入しない。
  - [ ] 収集元が一時的に応答しない／取得失敗しても、他ソースの収集は継続され、失敗は記録される（1ソースの失敗で全体が止まらない）。

### F6. 重複排除・正規化
- 説明: 同一の話題・同一ソースを重複して記事化しないよう、収集アイテム間および既存記事との重複を検出し、正規化（表記ゆれ・URL 正規化）した上で「未記事化キュー」に積む。
- 優先度: Must
- 受け入れ基準:
  - [ ] 同一 URL（正規化後）の収集アイテムを2回取り込んでも、記事化候補としては1件にまとめられる（重複が二重に記事化されない）。
  - [ ] タイトル・本文が高い類似度を持つ別 URL のアイテム同士を「同一話題の重複」として検出し、片方のみを記事化候補にする。
  - [ ] 既に記事化済みのソースは再度記事化候補にならない（同じスレッドから二重記事が生成されない）。
  - [ ] 重複排除の結果、記事化候補キューには一意な話題だけが残ることを、重複を含む入力セットで確認できる。

## このスプリントの受け入れ基準
- [ ] 収集を実行すると、Reddit／5ch／Riot 公式の各ソース（本番 API 未接続時はサンプル入力でよい）から、ソース種別・元URL・原題・本文または反応抜粋・取得日時を持つ共通フォーマットの収集アイテムが保存される。
- [ ] 出典（元URL）を持たない収集アイテムは保存されない。
- [ ] ソースごとの取得件数上限・実行間隔が設定として存在し、上限を超える連続取得をしないことを確認できる。
- [ ] LoL 関連に限定するフィルタが働き、無関係アイテム（別ゲーム・無関係スレッド）が混入しない。
- [ ] 1ソースの取得を意図的に失敗させても、他ソースの収集は完走し、失敗が記録される。
- [ ] 同一 URL（正規化後）を2回取り込んでも記事化候補は1件にまとまる。
- [ ] タイトル・本文が高類似度の別 URL 同士を同一話題として検出し、片方のみ候補にする。
- [ ] 既に記事化済みのソースが再度候補にならない。
- [ ] 重複を含む入力セットを流したとき、記事化候補キューに一意な話題だけが残ることを確認できる。
