# 拡張スプリント E12: まとめレスを1枠に統合表示＋コメントUIの差別化

対象プラットフォーム: web（既存アーキテクチャに従う）

## 背景
現状、5ch/reddit のまとめ速報記事は各レス（reactionブロック）が**個別の枠**で描画され、レスごとに枠が分かれている。
参考サイト（おばにゅー）は、まとめ本文のレス群を**1つの枠の中に連続して**並べる。また、まとめ本文のレスと
読者コメントが同じ見た目で見分けづらい。両者を参考サイトのように整理する。

## 含まれる機能

### F-E12-1: まとめ速報のレスを1枠に統合表示（おばにゅー準拠）
- 記事本文（`ArticleBodyView`）で、**連続する reaction ブロック群を1つの枠（コンテナ）にまとめて**描画する。
  各レスは枠内で縦に連続し、レス間は**軽い区切り線（薄いborder）**等で仕切る（レスごとに独立した角丸ボックスにしない）。
- 各レスの「番号: 名前（緑）＋本文行（逐語・複数行）＋赤/オレンジ強調＋`>>N`アンカー」の中身の表示は維持する（枠の付け方だけ変える）。
- reaction 以外のブロック（heading/paragraph/quote/image/embed）の表示は従来どおり。記事中の広告枠（`article-in-body`）の差し込み位置・挙動も維持する。
- 非連続の reaction ブロック（間に heading 等が挟まる場合）は、連続するまとまりごとに別々の枠にする（自然なグルーピング）。

### F-E12-2: コメントUIをまとめレスと別デザインに差別化
- 読者コメント欄（`comment-section.tsx` の `CommentRow`）の見た目を、まとめ本文のレス（`ResHeader`/`ResLines` の番号:名前緑スタイル）と**明確に区別できるUI**にする（おばにゅー準拠）。
  - 例: コメントは「番号: 名前」レス体裁をやめ、コメント用のヘッダー（アイコン/丸バッジ＋ハンドル名＋相対時刻）＋本文、という別レイアウトにする。背景色・境界・余白もまとめレスと変える。
  - まとめ本文のレスと読者コメントを画面上で一目で区別できること（配色・アイコン・ラベル等で差別化）。
- コメントの既存機能（E8の返信ボタン・ネスト表示・👍/👎・`>>N`アンカー・XSSエスケープ）は維持する。
- コメントのアンカー（`>>N`）や本文の表示（`commentBodyToLines`）自体は流用してよいが、レス見出し（`ResHeader`）の使い回しはやめてコメント専用ヘッダーにする（差別化の要）。

## 実装方針
- `ArticleBodyView` の描画ループで、連続 reaction ブロックをグルーピングして1枠にまとめる純粋な整形は、可能なら純関数（ブロック配列→描画グループ配列）に切り出して単体テストする。
- コメント専用のヘッダー/行コンポーネントを用意し、`ResHeader` 共用を解く。ダークモード・レスポンシブを維持。
- 過度な作り直しは避け、枠の付け方・コメントの体裁変更に留める。公開限定・モデレーション等の不変条件は変えない（表示のみ）。

## 受け入れ基準（検証可能・原文）
- [ ] まとめ速報型（5ch/海外の反応）の記事本文で、複数レスが**1つの枠**の中に連続表示され、レスごとの独立ボックスになっていない。
- [ ] 各レスの番号:名前（緑）・本文・赤/オレンジ強調・`>>N`アンカーの表示は維持されている。
- [ ] heading等を挟んで非連続な reaction は、まとまりごとに別枠になる。記事中広告の差し込みも従来どおり。
- [ ] 読者コメント欄が、まとめ本文のレスと**一目で区別できる別デザイン**になっている（配色/アイコン/レイアウトの差）。
- [ ] コメントの返信ボタン・ネスト表示・👍/👎・`>>N`アンカー・XSSエスケープが維持されている。
- [ ] ダークモード・レスポンシブが崩れない。コンソールエラー0件。
- [ ] `npm test` が全てGreen（reactionブロックのグルーピング整形など切り出した純関数に最小限のテストを追加）。

## 評価基準（evaluator向け）
- 致命的バグ0件／コンソール・実行エラー0件／上記受け入れ基準の充足率100%／テストGreen。1つでも下回れば全体FAIL。
- Playwright MCP でまとめ記事本文（1枠統合）・コメント欄（差別化）・ダーク/レスポンシブを確認。PC/モバイルのプレビュー画像を保存すること。
