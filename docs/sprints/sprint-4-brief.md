## 対象プラットフォーム
`web`（自動運営のバックエンド／バッチ処理を含む）。

## ⚠ このスプリントの実装方針（LLM もモック）
**AI 記事生成の LLM は当面モック／スタブ実装で進める**（ユーザー決定 2026-07-25: LLM 本接続もスキップし、まず全スプリントを通す）。architecture.md の `LLMClient` 抽象越しに呼び出し、既定は API キー不要の決定論的モック実装（テンプレート／ルールベースで、見出し・段落・出典付与・構成分岐・逐語一致率閾値を満たす日本語まとめ本文を生成する）にする。後日 Anthropic Claude（`ANTHROPIC_API_KEY`）へ差し替えられるよう抽象は維持すること。自動テストはこのモック経路で決定論的に Green にする。**API キーは要求しない**（evaluator もモック前提で判定し、本物の外部 LLM 連携としては判定しない）。

## 含まれる機能: F7

### F7. AI まとめ記事生成
- 説明: 記事化候補の収集アイテムを入力に、AI が日本語のまとめ記事本文（導入→反応／情報の要約・再構成→まとめ）を生成する。掲示板／Reddit のまとめは「反応をまとめた」構成、公式情報は速報記事構成にする。単なる複製ではなく要約・再構成・複数ソース統合で付加価値を持たせ、出典を明記する。
- 優先度: Must
- 受け入れ基準:
  - [ ] 記事化候補を入力すると、見出し・段落を持つ構造化された日本語のまとめ記事本文が生成される（1記事あたり本文が最低300文字以上）。
  - [ ] 生成本文は元ソースの逐語コピーではなく再構成されている（元本文と生成本文の逐語一致率が高すぎない＝定めた閾値以下であることを確認できる）。
  - [ ] 掲示板／Reddit 由来の記事は「複数の反応（コメント）を要約して並べる」構成、Riot 公式由来の記事は「事実の速報＋要点整理」構成で生成される。
  - [ ] 生成記事には出典（元スレッド／投稿／公式ページへのリンク）が本文または末尾に必ず含まれる。
  - [ ] 引用を含む場合、引用部分が記事全体に占める割合が過大でない（自サイト生成文が主・引用が従の主従関係を満たすことを確認できる）。
  - [ ] 生成に失敗した候補は「生成失敗」として記録され、他候補の生成は継続する。

## このスプリントの受け入れ基準
- [ ] 記事化候補を入力すると、見出し・段落を持つ構造化された日本語まとめ記事本文（最低300文字以上）が生成される。
- [ ] 生成本文と元ソース本文の逐語一致率が定めた閾値以下（＝逐語コピーでない）であることを、サンプル入力で確認できる。
- [ ] 掲示板／Reddit 由来は「複数の反応を要約して並べる」構成、Riot 公式由来は「速報＋要点整理」構成で生成される。
- [ ] 生成記事に出典リンクが本文または末尾に必ず含まれる。
- [ ] 引用を含む場合、引用が記事全体に占める割合が過大でなく、主従関係（生成文が主）を満たすことを確認できる。
- [ ] 生成に失敗した候補は「生成失敗」として記録され、他候補の生成が継続する。
- [ ] 生成された記事が Sprint 1 の閲覧サイトの個別記事ページに正しく表示される（見出し・段落・出典が崩れない）。
