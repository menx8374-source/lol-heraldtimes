# 拡張スプリント E9: 記事一覧の刷新（おばにゅー風・横広レイアウト＋1レス目本文プレビュー）

対象プラットフォーム: web（既存アーキテクチャに従う）

## 背景
参考サイト（おばにゅー）の記事一覧は、横幅を広く使い、各記事にタイトルだけでなく
「反応まとめの1レス目の本文抜粋」を載せて中身が分かるようになっている。本サイトの一覧も同様にする。

## 含まれる機能

### F-E9-1: 一覧カードに「1レス目の本文」プレビューを表示
- 記事一覧の各カードの見出し下に、記事内容が分かる抜粋を表示する。
- **reactionブロックを含む記事（まとめ速報型・5ch/reddit）**では、抜粋を「反応まとめの**1レス目のレス本文**」から生成する
  （添付例のように「1: 〜」という最初のレス内容が読めること）。番号プレフィックス表示の有無は自然な見え方に合わせてよいが、
  1レス目の実際の発言内容が抜粋に含まれること。
- reactionブロックを持たない記事（Riot公式形式など）は、従来どおり本文冒頭段落からの抜粋にフォールバックする。
- 抜粋の生成は `lib/articles.ts` の `excerpt` 導出（現在 `buildArticleExcerpt`）を拡張して行い、
  トップ・カテゴリ・タグ・検索・アーカイブなど全ての一覧で一貫して反映されること。
- 抜粋は適切な長さ（80〜120字程度）で省略（line-clamp等）し、レイアウトを崩さない。

### F-E9-2: 一覧レイアウトを横に広く・見やすく（おばにゅー風）
- 一覧のコンテナ幅・カード構成を見直し、横幅をより広く使った読みやすいレイアウトにする
  （左にサムネイル、右にタイトル＋プレビュー＋メタ情報を横並びにする横長カードなど）。
- PCでは横幅を活かし、モバイルでも破綻しないレスポンシブを維持する。
- サイドバー（人気ランキング等）との併存レイアウトを崩さない。ダークモードも維持する。
- 対象は記事一覧が出る全ページ（トップ、カテゴリ、タグ、検索結果、月別/日別アーカイブ）。

## 実装方針
- 抜粋ロジックは純関数として切り出し、reactionブロック優先→フォールバックの分岐を単体テスト可能にする。
- 既存の `ArticleCard` / `ArticleList` / `PageWithSidebar` のレイアウトを調整する。過度な作り直しはせず、幅・段組・カード内配置の改善に留める。
- 既存のE7ピン留め（📌注目バッジ・先頭優先）表示は維持する。

## 受け入れ基準（検証可能・原文）
- [ ] トップの記事一覧で、各まとめ速報型記事のカードに「反応まとめの1レス目の本文」が抜粋表示される。
- [ ] reactionブロックの無い記事は本文冒頭からの抜粋が表示される（空欄にならない）。
- [ ] カテゴリ・タグ・検索・アーカイブの各一覧でも同じ抜粋が一貫して表示される。
- [ ] 一覧が以前より横幅を広く使った、タイトル＋プレビューが読みやすいレイアウトになっている。
- [ ] PC・モバイル双方でレイアウトが破綻しない（レスポンシブ・ダークモード維持）。
- [ ] ピン留め記事の📌注目バッジ・先頭表示が維持されている。
- [ ] `npm test` が全てGreen（抜粋導出の分岐に最小限のテストを追加）。

## 評価基準（evaluator向け）
- 致命的バグ0件／コンソール・実行エラー0件／上記受け入れ基準の充足率100%／テストGreen。1つでも下回れば全体FAIL。
- Playwright MCP でトップ・カテゴリ・タグ・検索・アーカイブの一覧表示、PC/モバイル幅、ダークモードを確認。プレビュー画像を保存すること。
