## 観点ごとの結果（すべてPASS）
1. **コメント投稿→公開表示**: フォームに名前+本文を入力し送信→「6: 検証テスター / たった今 / >>1 …」形式で即時表示。番号・名前・相対時刻付き。リロード後も残存（DBに永続化を確認）。
2. **コメント数の連携**: 投稿後、コメント欄見出し「コメント (5)→(6)→(7)」・個別記事上部・トップページ記事カードの💬（jungle=7, yasuo=3, worlds=4）が一致。DBの`Article.commentCount`も7で整合。
3. **安全フィルタ**: NGワード（「カス」「死ね」）／個人中傷（「田中選手は本当に無能だ…」）を投稿→いずれも公開されず、コメント数も増えず（7のまま）、穏当なメッセージ「不適切な内容が含まれる可能性があるため…」を表示。DBには`status=held`（heldReason=ng_word / personal_attack）で記録のみ、公開一覧・新着ウィジェットには非出現。
4. **XSS安全**: `<script>alert('xss')</script><b>tag</b>` を投稿→アラート発火せず。DOM出力は `&lt;script&gt;…&lt;/script&gt;&lt;b&gt;tag&lt;/b&gt;` とエスケープされ、`li script`要素0件・`<b>`要素も生成されず。新着コメントウィジェットでも同様にエスケープ表示。
5. **`>>N`アンカー**: `>>1`等がオレンジ（`[class*="orange"]`）で別要素表示。名前は緑クラスで表示。
6. **新着コメントウィジェット**: サイドバー「新着コメント」に全記事横断で直近5件（抜粋+記事タイトルリンク`/articles/<slug>#comments`+相対時刻）。新しい順（「たった今」が先頭）。held/非公開記事のコメントは非表示。
7. **回帰・整合**: held公開なし。反応まとめ記事表示・ページネーション（`/?page=2`=200）・リアクション（👍6→7でインクリメント動作）・ダークモード（html.darkトグル動作）・法務ページ（/privacy・/disclaimer・/contact=200）・`/admin`分離（運営監視ダッシュボード表示、公開コメントフォーム/新着ウィジェットなし）すべて正常。横スクロールなし（scrollWidth 1905 ≤ innerWidth 1920）。

## 軽微な改善点（ブロッカーではない）
- モデレーション保留(held)は HTTP 422、バリデーション拒否・スパムは HTTP 400 を返すため、ブラウザのネットワーク層が「Failed to load resource: 422/400」をコンソールに自動出力する（アプリのJSエラーではなく、`fetch`で4xxを扱う際の標準的な副作用。UIは穏当なメッセージで正常処理し、既存のリアクションAPIも同一パターン）。厳密なコンソール無音を求めるなら、held/rejectを 200 + `{status:"held"|"rejected", message}` で返してクライアント側で分岐表示する設計も選択肢。今回は機能・UXに影響がなく、アプリ不具合ではないためPASS判定を妨げない。
- コメント投稿フォームの名前/本文入力欄は可視ラベル（「名前（任意…）」「コメント」）付きでアクセシビリティ上の問題は特になし。
