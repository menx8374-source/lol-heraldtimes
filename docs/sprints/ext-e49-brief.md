# 拡張E49 — 海外の反応(Reddit)翻訳の堅牢化（記事まるごと英語のままになる問題の解消）

運用フィードバック起点。対象: Web。

## 背景（なぜ・現象）
E47でReddit反応記事のコメントを日本語訳＋原文併記にしたが、**ある記事だけ全コメントが未翻訳（英語のまま）**に
なることがある（例「【悲報】Azir…最低勝率チャンプに成り下がる」）。他の海外の反応記事は正常に翻訳される。

原因（E47実装の弱点）:
1. **1記事分の全レス行を1回のLLM呼び出しでまとめて翻訳**しており、コメントが多い/長い記事では出力JSONが
   大きくなり**途中で切れて `JSON.parse` 失敗→null→記事まるごと英語フォールバック**になりやすい。
2. `normalizeTranslations` が「そのレスの訳の**行数が原文と厳密一致**」しないとそのレスの訳を**捨てる**ため、
   LLMが行を結合/分割しただけで英語に落ちる。多数のレスで起きると記事がほぼ英語になる。

## 含まれる機能

### F-E49-1: 翻訳呼び出しの分割（巨大JSON途中切れの回避）
- `translateReactionLines` を、全レスを1回で送るのではなく **バッチに分割**して翻訳する:
  - `REDDIT_TRANSLATE_BATCH_SIZE`（env、既定6）レスごと、または合計文字数の上限（例 3000字）でバッチを区切る
    （どちらか実装しやすい方＋両方の安全上限でよい）。
  - 各バッチを個別にLLM翻訳し、結果の Map をマージする。**あるバッチの失敗（null/parse不能）は、そのバッチの
    レスだけ英語フォールバック**にし、他バッチの訳は活かす（記事まるごと英語にしない）。
  - バッチが空応答/parse失敗のときは**1回だけ再試行**してよい（基盤の一時失敗対策・任意）。
  - LLM呼び出し回数は「記事のレス数 / バッチサイズ」（例 12レスなら2回程度）に増えるが、Haikuで安価。5ch は従来どおり呼ばない。

### F-E49-2: 行数不一致でも訳を活かす（レスまるごと英語に落とさない）
- `normalizeTranslations` の「行数厳密一致でないと捨てる」を緩める。**index が有効で lines が非空文字列配列**なら
  そのレスの訳（LLMが返した行配列）を採用する（行数一致は必須にしない）。
- `buildReactionBlocks`（reddit）でのレス組み立てを次のように堅牢化:
  - そのレスに訳がある場合:
    - **行数が原文(extractedLines)と一致** → 従来どおり行単位で `{text:日本語行, original:英語行}`。
    - **行数が不一致** → そのレスを**1つのまとまった行に束ねて** `{text: 日本語訳を改行結合, original: 英語原文を改行結合}`
      とする（訳を捨てず採用。原文併記も保持）。
  - そのレスに訳が**全く無い**（バッチ失敗）場合のみ、従来どおり `{text: 英語原文}`（original無し）で英語フォールバック。
- NG文削除・行強調は、E47同様「表示テキスト（訳があれば日本語）」に適用する。束ねた行にも同様に適用する
  （束ね後の text にNGが含まれ空になれば従来どおりその行/レスを落とす）。

## 制約・非目標
- **reddit のみ**。5ch/riot・NG・強調色・サムネ・収集(reddit.ts)・翻訳プロンプト方針（捏造禁止・LoL用語日本語化）には
  実質触れない（プロンプトは維持。分割と適用ロジックのみ変更）。新規npm依存なし。逐語は「原文英語を original に保持」で担保。
- mock既定は従来どおり英語のまま（翻訳は live 時のみ・回帰なし）。
- 「全レスの完全翻訳」を保証はしない（バッチ失敗レスは英語）。ただし**記事まるごと英語になる確率を大きく下げる**のが目的。

## テスト（必須・実API/実ネット非依存＝スタブLLM）
1. `translateReactionLines`（スタブ）: レス数がバッチサイズ超のとき複数回呼ばれ、結果がマージされる。1バッチだけ
   null/parse失敗のとき、そのバッチのレスのみ訳が欠け（＝呼び出し側で英語FB）、他バッチは訳される。
2. `normalizeTranslations`: 行数不一致でも非空文字列配列なら採用される（従来の「不一致は捨てる」から変更）。index無効・
   非文字列・空要素は従来どおり除外。
3. `buildReactionBlocks`（reddit・スタブ翻訳）:
   - 行数一致レス → 行単位で `{text:日本語, original:英語}`。
   - 行数不一致レス → 1行に束ねた `{text:日本語(改行結合), original:英語(改行結合)}`（英語に落ちない）。
   - 訳が無いレス → `{text:英語}`（original無し）。
   - NG・強調が表示テキスト（日本語）に適用される。
4. `buildReactionBlocks`（5ch）: 翻訳を呼ばず従来どおり（不変・回帰なし）。
5. 既存 E47/compose/reaction テストが新仕様に沿って回帰しない（厳密一致前提だったものは束ね採用に更新）。

## 受け入れ基準
1. `npx vitest run` 全Green（新規/更新含む・実API/実ネット非依存）。
2. `npx tsc --noEmit`・`npm run build`・`npm run lint` 通過。
3. コメントが多い/長いreddit記事でも、記事まるごと英語になりにくい（バッチ分割＋行数不一致でも訳採用）。訳が取れない
   レスのみ英語フォールバック。5chは不変・翻訳はreddit時のみ・新規依存なし。

## 評価基準（evaluator向け）
- テストGreen・build/tsc/lint通過。mock/生成パイプラインが回帰しない（5ch不変・reddit mockは英語・コンソールエラー0）。
- バッチ分割・行数不一致時の束ね採用・訳無しレスの英語FBがテストで確認できる。
- 受け入れ基準1〜3を満たす。
