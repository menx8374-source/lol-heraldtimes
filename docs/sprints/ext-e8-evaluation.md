## 軽微な改善点（ブロッカーではない）
- moderation-held 投稿時、サーバーがHTTP 422を返すため browser DevTools に `Failed to load resource: status 422` が自動記録される（トップレベル・返信で共通）。UXは適切なメッセージで処理済み・機能に影響なし。気になる場合は held を 200+`{status:"held"}` で返す設計も選択肢（ただしこれはE2から続く既存挙動でありE8の担当範囲外）。
- 検証中、curlでの日本語POSTはシェルのUTF-8エンコーディング破損で本文が化けNGワード判定を素通りした（201）。これは検証ハーネスの制約であり、アプリ不具合ではない（同内容をPlaywright UI経由で送ると正しくheldになる）。破損したテストコメントはレポート作成前に `npm run db:seed` で初期化済み。

## 未検証項目（実機確認が必要）
- held/scheduled/rejected 記事の「コメントへの投票拒否」: シードに非公開記事が存在しないためAPI直叩きでの実機再現は不可。ただし held コメントへのvote拒否（404・無加算）を実機確認済みで、ルートは PUBLISHED_ONLY 共有フィルタ、unit test でも非公開記事の不加算をカバー。実質的にカバー済みと判断。
