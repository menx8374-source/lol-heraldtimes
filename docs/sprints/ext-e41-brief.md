# 拡張E41 — 反応記事の返信先レスも引用＋パッチ記事を事実速報に戻す

運用フィードバック起点。対象: Web。

## 背景（なぜ）
1. 反応記事で「61: >>58 拮抗してるゲームが…」のように**アンカー(>>58)で返信しているのに、返信先の58番が
   引用されていない**ため文脈が分からない。表示するレスが `>>N` で他レスを参照している場合、その参照先Nも
   一緒に引用したい。
2. パッチ記事は現状「LLM要約／決定的な変更点抽出」だが、**今は事実速報（パッチが公開された、という簡潔な速報）に
   したい**（後でLLMまとめに戻す可能性があるため、コードは残して切替可能にする）。

## 含まれる機能

### F-E41-1: 表示レスの返信先（アンカー先）も引用する
2層で「表示・抽出するレスが `>>N` で参照する先Nも含める」ようにする（Nが存在する場合・1階層のみ）。

- **compose.ts `buildReactionBlocks`（表示レス選定・主目的）**:
  - LLM/フォールバックで選ばれた表示レス（`selectedIndices`）について、各レスの**実際に表示する行**
    （`keepLines` 指定があればその行、なければ全行）から `extractAnchors` で `>>N` を集める。
  - 参照先 N が `reses` に存在し（レス番号→index の対応表を作る）、まだ選ばれていなければ、その index を
    表示対象に**追加**する（文脈として全行・強調なしで表示。NG文削除は通常どおり適用）。
  - 追加は**1階層のみ**（追加した文脈レスがさらに参照する先は辿らない＝無限展開を防ぐ）。
  - 最終的な表示 index は**元スレ順（index昇順＝レス番号順）**に整列してから組む（返信先が返信元より前に出る）。
  - 上限 `MAX_EXCERPT_RESES`(12) は選定（keep）に対する上限のままとし、アンカー文脈で数件超えるのは許容
    （文脈の可読性を優先）。ただし際限なく増やさない（1階層＋既存レスのみなので有界）。

- **fivech.ts `selectHighlightReses`（収集ダンプの自己完結化・補助）**:
  - 収集時のスレッドダンプに参照先レスが**そもそも含まれていない**と compose 側でも復元できないため、
    選抜したレスが `>>N` で参照する先N（`valid` に存在するもの）も、まだ無ければ含める（best-effort）。
  - `maxReses` の上限は維持する（際限なく増やさない）。上限に達している場合は、被参照カウントが最も低い
    非OP・非アンカー先のレスを1つ落としてアンカー先のための枠を空ける、等の決定論的な方法で上限内に収める
    （実装しやすい形でよい。要は「選抜レスの直接の返信先も可能な範囲でダンプに含める」）。

### F-E41-2: パッチ記事を事実速報にする（LLMまとめ/抽出は残して切替可能に）
- `compose.ts` に**事実速報のパッチ本文** `composePatchFactFlashBody`（仮称）を追加する:
  - 見出し「パッチ<番号>が公開」＋短い事実段落（例「リーグ・オブ・レジェンドのパッチ26.14が公開されました。
    チャンピオンやアイテムのバランス調整が行われています。詳しい変更内容は公式パッチノートをご確認ください。」）
    ＋出典（公式パッチノートURL）。**謝罪文言（「自動要約では抽出できなかった」等）は入れない**（意図的に
    要約しない事実速報のため）。捏造禁止（具体的な数値・チャンピオン名は書かない＝一般的な事実のみ）。
- `composeArticleBody` の riot 分岐を、環境変数 `PATCH_ARTICLE_MODE` で切替:
  - `"fact"`（**既定**）: 常に `composePatchFactFlashBody`（本文の長短に関わらず事実速報）。
  - `"summary"`: 従来のE40の3段（`composePatchSummaryBody`(LLM要約) → `extractPatchChangesDeterministic`(決定的抽出)
    → `composeCleanPatchFallbackBody`）。後でLLMまとめに戻すとき用に**コードとテストは残す**。
- `.env.example` に `PATCH_ARTICLE_MODE`（既定 fact／summary で従来のまとめ）を追記（秘密情報ではない）。
- タイトルは E40 のまま（riot は `candidate.title` の事実タイトル。捏造なし）。

## 制約・非目標
- 逐語維持（レス本文・パッチ本文の具体値は書き換えない／事実速報は一般的事実のみで捏造しない）。新規依存なし。
- 反応記事のNG・強調色・サムネ、他ソース、5ch収集のそれ以外の挙動には触れない（アンカー先追加のみ）。
- mock既定は回帰なし（パッチ事実速報はmock/liveどちらでも決定論。LLM呼び出しは増やさない＝factモードはLLM不使用）。
- アンカー先追加は1階層のみ。存在しない番号(>>N)は従来どおり無視（範囲外アンカーはテキストとして残るだけ）。

## テスト（必須・実API/実ネット非依存）
1. F-E41-1 compose: 表示レス（例 index 61）が `>>58` を含み、58が content に存在するとき、58も表示ブロックに
   含まれる（レス番号順で58→61）。58が存在しない番号なら追加されない（従来どおり）。追加された文脈レスは
   強調なし・全行。1階層のみ（58がさらに>>50を参照しても50は追加しない）。keepで行を絞った場合、絞った行の
   アンカーのみ対象。
2. F-E41-1 fivech `selectHighlightReses`: 選抜レスの直接の `>>N` 先が `valid` にあれば、maxReses 内で含まれる。
   上限は超えない。
3. F-E41-2: `PATCH_ARTICLE_MODE` 未設定/`"fact"` で riot 記事が事実速報本文（見出し「パッチ<番号>が公開」＋
   事実段落＋出典・謝罪文言なし・具体数値なし）になる。`"summary"` で従来のE40 3段フォールバック（LLM要約→決定的抽出→
   クリーン定型）になる（回帰なし）。
4. 既存の compose/patch/reaction/pipeline テストが本仕様に沿って回帰しない（riot本文の既定期待を事実速報に更新）。

## 受け入れ基準
1. `npx vitest run` 全Green（新規/更新含む・実API/実ネット非依存）。
2. `npx tsc --noEmit`・`npm run build`・`npm run lint` 通過。
3. 反応記事で表示レスの返信先(>>N)も引用され文脈が分かる。パッチ記事が既定で事実速報になり、`PATCH_ARTICLE_MODE=summary`
   で従来のまとめに戻せる。逐語維持・捏造なし・新規依存なし・LLM呼び出し増なし。

## 評価基準（evaluator向け）
- テストGreen・build/tsc/lint通過。mock/生成パイプラインが回帰しない（コンソールエラー0）。
- アンカー先引用の追加（1階層・番号順）、パッチ事実速報とsummary切替がテスト/データで確認できる。
- 受け入れ基準1〜3を満たす。
