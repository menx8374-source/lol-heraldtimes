# 拡張E39 — 5ch収集の改善（A:収集の質 / B:アクセス作法 / D:可観測性）

運用フィードバック起点。5ch live アダプタ（`src/lib/collection/adapters/fivech.ts`）の質・作法・可観測性を上げる。対象: Web（バックエンド収集）。

## 背景（なぜ）
現状の5ch収集は「subject.txt→タイトルキーワードでスレ絞り→dat取得→**先頭30レス**をダンプ」というベストエフォート。
- 先頭30レス＝スレ冒頭のテンプレ・過疎部分で、まとめとして一番つまらない箇所を切り出している。
- スレ選別がキーワード一致→subject順で先頭N件slice のみで、レス数（勢い）での足切り・並べ替えが無い。
- 関連語が英語偏重で日本語スレを取りこぼす。
- dat連続取得にウェイトが無く、板を完全並列取得しており403/BANリスクがある。
- 取得0件の理由（403で弾かれた/関連スレ無し）が実行ログに残らず、完全自動運用でサイレントに枯れる恐れ。

**C（転載リスク＝open2ch化）は今回のスコープ外**（5ch継続）。

## 含まれる機能

### F-E39-A1: 「盛り上がったレス」優先抽出（先頭30固定をやめる）
- `src/lib/collection/adapters/fivech.ts` の dat→ダンプ整形を、先頭N固定から「被参照（アンカー）の多いレス優先」に変える。
- 純関数として実装（単体テスト可能に）:
  - dat全体を全レス `{ number, bodyLines }` にパースする（number＝dat行番号=レス番号、1始まり）。
  - 各レスの**被参照カウント**（他レス本文の `>>number` から参照された回数）を集計する。アンカー抽出は
    既存 `extractAnchors`（`@/lib/generation/thread-format`、純関数・再利用）を使う。
  - **レス1（スレ主題/OP）は文脈として常に含める**。残り枠を被参照カウント降順（同数はレス番号昇順）で埋め、
    合計が `maxReses`（既定は現行 `MAX_RESES_PER_THREAD`=30 を流用）以下になるよう選ぶ。
  - 選んだレスを**元のレス番号のまま昇順**に整列し、既存と同じ「`N: 本文\n\n…`」ダンプ形式で返す
    （**元番号維持が必須**。`parseThreadReses` は非連続番号・範囲外 `>>N` を安全に扱えるため下流互換）。
  - 本文が空のレスは除外。有効レス0なら null（現行同様）。
- ねらい: アンカーが集まる＝議論の核・面白い応酬を優先的にまとめに載せる。逐語は不変（選定のみ、本文は書き換えない）。

### F-E39-A2: スレ選別の改善（レス数足切り＋勢い順）
- `filterRelevantThreads`（またはリネームした純関数）を拡張:
  - キーワード関連度は従来どおり（`filterRelevantThreads` の一致判定）。
  - **レス数の下限** `FIVECH_MIN_RES_COUNT`（env、既定20）未満のスレを除外（過疎スレ排除）。
  - 残りを **resCount 降順（勢い proxy）** でソートしてから上位 `limit` を採用（subject順のsliceをやめる）。
  - 満了（1000到達）スレは内容が豊富なので除外しない（上限では切らない）。
- 純関数として単体テスト可能に保つ。

### F-E39-A3: 関連語の拡充（日本語・カタカナチャンピオン名・大会名）
- `src/lib/collection/config.ts` の `DEFAULT_LOL_KEYWORDS` に、5chの日本語スレタイに当たる語を**厳選して**追加:
  - 用語: `リーグオブレジェンド`,`LJL`,`LCK`,`LEC`,`LPL`,`MSI`,`世界大会`,`ソロキュー`,`ランク戦`,`ナーフ`,`バフ`,`集団戦`,`ガンク`,`レーン`,`対面` など。
  - 主要チャンピオン（カタカナ・厳選、誤検出増を避け全160体は入れない）: `アーリ`,`ゼド`,`ジンクス`,`リー・シン`,`ルシアン`,`カタリナ`,`イレリア`,`ヴェイン`,`セト`,`ヨネ`,`ヤスオ`(既存),`アカリ` など10〜15体程度。
  - 過度に一般的で誤検出しやすい単語（例: `メタ`,`トップ`単独 等）は避ける。
- 既存の英語キーワードは維持（reddit等の英語タイトルにも効く）。

### F-E39-B1: アクセス作法（ウェイト＋直列化）
- dat/subject の連続取得の間に**ディレイ**を入れる。`FIVECH_REQUEST_DELAY_MS`（env、既定1500）。
- 板取得を **`Promise.all` の完全並列からやめ、直列**にする（同一サーバへの同時多重接続を避ける）。
  スレごとの dat 取得も直列＋各取得前にディレイ（先頭は不要でよい）。
- **テスト容易性**: `FiveChAdapterOptions` に `delayMs?: number` と `sleep?: (ms:number)=>Promise<void>` を追加し、
  テストでは `delayMs:0` かつ `sleep` をスパイ/noop注入して実待機しない。既定は実 setTimeout ベースの sleep。
- 挙動: 収集は低頻度cron前提なので、直列＋1.5s間隔の総遅延は許容範囲。1ソースの遅延が全体を止めない方針は維持
  （失敗は従来どおり握り潰し）。

### F-E39-D1: 取得の可観測性（per-boardログ）
- `fetchBoardItems` / `fetchItems` で、**板ごとに** `subject取得件数 / 関連スレ数 / 採用スレ数（collected items）` を
  `console.log` に1行で出す（例: `[5ch] board=egg.5ch.net/livegame subject=120 relevant=8 selected=5 collected=5`）。
- subject.txt が取れなかった（403/ネット断）場合は、その旨を board 付きで**理由が分かる**ようログする
  （http.ts が既に status を出すので、board単位で「skip: subject取得失敗」を補足）。
- 収集全体の最後に合計（`collected=N`）を1行。ログはSourceAdapterの戻り値契約（`RawCollectionItem[]`）を変えず
  console出力に留める（構造変更しない）。**秘密情報は出さない**（UA・URLの非秘密情報のみ）。

## 制約・非目標
- **live アダプタ（5ch）のみ**。mock収集・他ソース（reddit/riot/clip）・生成/表示層・NG・強調色・サムネには触れない。
- 逐語維持（レス選定・スレ選定・並べ替えのみ。レス本文は一切書き換えない）。新規npm依存なし。
- 下流の `parseThreadReses`/compose 契約を壊さない（**元レス番号維持**・`N: 本文` 形式・空行区切り）。
- C（open2ch化）は対象外。dat直アクセスのHTTPフォールバック（read.cgi化）も今回は対象外（別スプリント）。

## テスト（必須・実API/実ネット非依存）
1. A1 抽出（純関数）: 被参照の多いレスが選ばれ、レス1が常に含まれ、出力は**元番号昇順**・`N: ` 形式。maxReses超は上位のみ。
   範囲外/欠番アンカーを含む dat でも壊れない。逐語（本文）不変。
2. A2 スレ選別（純関数）: resCount<MIN のスレが除外され、残りが resCount 降順で limit 件。キーワード不一致は除外。
3. A3 キーワード: 追加した日本語/カタチャン/大会名で日本語スレタイ（例「LJLの試合結果」「アーリ強すぎ問題」）が
   relevant 判定になる。既存英語キーワードの判定は回帰しない。
4. B1 ディレイ: `sleep` をスパイ注入し、複数スレ/複数板の取得で**取得間に sleep が呼ばれる**こと（回数/間隔）。
   `delayMs:0`+noop注入で実待機せずテストが速いこと。板が直列に処理されること。
5. D1 ログ: `console.log`/`console.error` をスパイし、per-board サマリ（subject/relevant/selected件数）と
   subject取得失敗時の board 付き skip ログが出ること。
6. 既存 `collection-fivech.test.ts` の「先頭30前提」等が新仕様に沿って更新され、全体が回帰しない。

## 受け入れ基準
1. `npx vitest run` 全Green（新規/更新含む・実API/実ネット非依存）。
2. `npx tsc --noEmit`・`npm run build`・`npm run lint` 通過。
3. 5ch収集が「盛り上がったレス優先抽出・レス数足切り＋勢い順・関連語拡充・取得間ウェイト＋直列・per-boardログ」で動く。
   逐語維持・下流契約維持・mock/他ソース不変・新規依存なし。

## 評価基準（evaluator向け）
- テストGreen・build/tsc/lint通過。mock収集・生成パイプラインが回帰しない（コンソールエラー0で反応記事が従来どおり出る）。
- A1/A2/A3/B1/D1 が単体テストで確認できる（実ネットに出ない）。
- 受け入れ基準1〜3を満たす。
