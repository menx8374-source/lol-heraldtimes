# 拡張E54 — 詳細パッチ記事にアイテム・システム変更も臨機応変に含める（チャンピオン以外の変更点の一般化）

運用フィードバック起点（パッチによってはアイテム仕様変更・システム変更もある→パッチノートの内容に応じて臨機応変に）。対象: Web。

## 背景（なぜ）
E53でパッチ記事を「チャンピオンごとに画像＋変更前後」まで詳細化した。しかしパッチノートには**アイテム/ルーンの仕様変更や
システム変更**が含まれる回もある。E53はチャンピオン名の節だけを抽出するため、それ以外の変更が記事に出ない。
**その回のパッチノートに載っているものに応じて**、チャンピオン以外（アイテム・システム等）の変更点も詳細に載せたい
（無い種類は出さない＝臨機応変）。

## 含まれる機能

### F-E54-1: 変更点抽出を「チャンピオン以外の変更」も拾う形に一般化（compose.ts）
- 既存 `extractPatchChangesDeterministic`（E40・チャンピオン名の節ごとに逐語「A ⇒ B」を抽出）を土台に、
  **チャンピオン節に属さない変更（アイテム/ルーン/システム等）も抽出**する。
- 一般化した抽出（純関数・決定的・逐語・捏造なし）:
  - チャンピオン節: 従来どおり（チャンピオン名の行を節開始、`⇒`変更行を逐語収集）。→ 画像付きで表示（E53）。
  - **チャンピオン以外の変更**: チャンピオン節に取り込まれなかった `⇒` 変更行（＋直前のラベル行＝アイテム名/スキル/項目）を、
    **直前の「セクション見出しらしい行」でグルーピング**して収集する。
    - セクション見出しの推定（ヒューリスティック・best-effort）: パッチノート内の上位見出し（例「アイテム」「ルーン」
      「アリーナ」「システム」「バグ修正」「その他」等のキーワードを含む短い行、または `⇒` を持たず直後に変更行が続く短い行）。
      該当が特定できない変更はまとめて総称見出し（例「その他の変更点」）に入れる。
  - 有界化: チャンピオン最大 ~12体（E53のまま）＋非チャンピオンのセクション最大 ~8個・各セクションの変更行最大 ~8行程度。
  - **その回のパッチに存在するものだけ**返す（アイテム/システム変更が無ければ空＝出さない）。

### F-E54-2: 詳細本文の組み立てを一般化セクションに対応（composeDetailedPatchBody）
- E53の `composeDetailedPatchBody` を、一般化抽出の結果に合わせて拡張:
  - バナー画像→見出し「パッチ<番号> の変更点」＋導入（E53のまま）。
  - **チャンピオンの変更**（あれば）: チャンピオンごと[見出し＋スプラッシュ画像＋逐語変更点]（E53のまま）。
  - **チャンピオン以外の変更**（あれば）: セクションごと[見出し（アイテム/システム等の見出し）＋逐語変更点の段落]
    （チャンピオン画像は付けない。アイテムアイコンは今回対象外＝テキストのみ）。
  - 公式リンクボタン（E53のまま）。
  - **臨機応変**: チャンピオン変更しか無いパッチはチャンピオン節のみ、アイテム/システム変更もあるパッチはそれらの節も出る。
    変更点が全く取れない/本文無しは従来どおり `composePatchFactFlashBody`（事実速報）にフォールバック。
- 逐語維持（変更点は本文の部分文字列のみ）・捏造なし・AI不使用（決定的抽出＋公式画像）。

## 制約・非目標
- アイテムアイコン画像・バフ/ナーフの厳密な分類・目次(TOC)・新スキン節は対象外（後続余地）。今回は「チャンピオン以外の変更点も
  臨機応変にセクション表示する」ことが主眼。
- チャンピオン節の既存挙動（E53）は不変。5ch/reddit・hotness・moderation・翻訳・SEO・riot-news には触れない。新規依存なし。
- セクション見出し推定はbest-effort（完璧な構造化は狙わない）。過度に飲み込まず、明らかにノイズ（ナビ断片等）は入れない。

## テスト（必須・実API/実ネット非依存＝fixture/スタブ）
1. 一般化抽出（純関数）: チャンピオン節＋アイテム/システム節を含む fixture から、チャンピオンは従来どおり、非チャンピオンの `⇒` 変更が
   セクション見出しでグルーピングされて抽出される（逐語）。有界化（節数・行数上限）。存在しない種類は空。
2. チャンピオンのみの fixture（＝現行パッチ相当）: 非チャンピオン節は空で、E53と同じチャンピオン節のみ（回帰なし）。
3. `composeDetailedPatchBody`: チャンピオン節（画像付き）＋非チャンピオン節（見出し＋変更点・画像なし）＋linkButton の順。臨機応変
   （アイテム/システムが無ければその節は出ない）。変更点無しは fact-flash フォールバック。
4. 逐語一致率チェック（generate-article）を通ること（実データ相当のfixtureで GenerationError にならない）。
5. 既存の compose/patch/detailed テストが回帰しない。

## 追加修正（実データ検証で判明・E54 v1の不具合）
実パッチ26.14で detailed 生成を検証したところ、非チャンピオン節の抽出が**スキル/ステータスのラベルを見出しに誤昇格**した
（「Rのダメージ」「Eの掴み後の移動距離」「Qの減少体力反映率」「固有スキルの魔力反映率」等が独立セクション化・「バグ修正」重複）。
原因は「⇒を持たない短い行＋直後に変更行→アドホック見出し」ヒューリスティックがスキルラベルやリスト外チャンピオンの
変更行ラベルを新セクションと誤認したため。以下に直す:
- **アドホック見出しヒューリスティックを廃止**する。
- **非チャンピオン節の見出しは、明示的なセクションキーワードを含む行のみ**に限定（例「アイテム」「ルーン」「アリーナ」「システム」
  「バグ修正」「その他」「メイヘム」等の章/モード名キーワードを含む短い行）。スキル記号(Q/W/E/R/固有スキル/パッシブ)や
  「〜のダメージ/反映率/移動距離/生成量」等の項目ラベルは**見出しにしない**。
- **どのセクションにも属さない ⇒ 変更**（チャンピオン未検出分・章見出し外）は、個別に見出し化せず、まとめて**単一の
  「その他の変更点」**セクションに入れる（それも無ければ省略）。1項目ごとにセクションを作らない。
- **同一見出しのセクションはマージ/重複排除**（「バグ修正」は1つ）。
- 検証: パッチ26.14の detailed 生成の見出しが**チャンピオン名＋ごく少数の正当な章見出し（バグ修正・アイテム等）のみ**になり、
  スキル/ステータスのラベルが見出しに出ない・「バグ修正」重複なし、をテスト（実データ相当fixture）で担保。

## 受け入れ基準
1. `npx vitest run` 全Green（新規/更新含む）。
2. `npx tsc --noEmit`・`npm run build`・`npm run lint` 通過。
3. パッチ記事が、その回のパッチノートに応じて**チャンピオン＋（あれば）アイテム/システム変更**を逐語で詳細表示する
   （無い種類は出さない）。捏造なし・逐語維持・AI不使用・新規依存なし・変更点無しは事実速報にフォールバック。

## 評価基準（evaluator向け）
- テスト全Green・build/tsc/lint通過。mock/生成が回帰しない（本文無し時はfact-flash・コンソールエラー0）。
- 非チャンピオン変更のセクション抽出・詳細本文への反映・臨機応変（存在するものだけ）がテスト/データで確認できる。
- 受け入れ基準1〜3を満たす。
