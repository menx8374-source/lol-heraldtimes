# パッチ刷新S7 — 11パッチ実データで全構造パターンを堅牢化（大型26.1・前シーズン含む）

S6で記述式変更・h3無し・非pcb・多様h4に対応したパーサを、**11パッチ（大型26.1〜通常パッチ〜前シーズン25系）の実HTMLで総当たり検証**し、崩れ・欠落・誤帰属を残さず堅牢化する。S6で据え置いた懸念（アリーナ対象名・個別ラベル）も解消する。**AI不使用**。対象: Web。

## 背景（S6の到達点と残課題）
- S6でパーサは記述式変更/h3無し/white-stone/多様h4に対応（アジールW=記述式3件が表示されるようになった）。
- ただしS6は5パッチ（26.10〜26.14）のみで検証。ユーザー要望により**大型パッチ26.1（676KB・28セクション）を含む11パッチ**で総当たり検証し、あらゆる構造に耐えるようにする。
- S6 selfeval の残課題（本スプリントで解消）:
  1. **アリーナ節の対象名が「チャンピオン」になる**（h3無し・先頭h4を対象名に消費するルールの副作用）。→ セクション文脈を使い適切な対象名にする。
  2. **`<p><strong>個別名</strong></p>` という中間ラベル**（アリーナ/オーグメントの個別名）が1グループに統合され個別名と紐付かない。→ 中間ラベルを小見出し/対象名として扱えるようにする。

## 分析対象（generatorは必ず全部Readして構造を把握）
`src/lib/generation/__fixtures__/patches/patch-{26-1,26-2,26-3,26-10,26-11,26-12,26-13,26-14,25-13,25-19,25-24}.html`（実HTML・計11パッチ）。特に:
- **大型26.1**: ロールクエスト/エピックオブジェクト/ジャングル/タワー/ミニオン/新アイテム/復活するアイテム/アップデートされたアイテム/オムニヴァンプ/メイヘム/デマーシア建国譚 等、通常パッチに無い多数のシステム系セクション。
- **前シーズン25系**: 旧マークアップの差異がないか。
- オーグメント/アリーナ/ルーン/バグ修正の各構造バリエーション。

## 含まれる機能

### F-S7-1: 11パッチ総当たりでの堅牢化（patch-notes-parser.ts）
全11パッチをパースして、以下を保証する:
- **崩れゼロ**: どのパッチ・どのセクションでも例外を投げず、対象・グループ・変更が構造どおりに紐づく。想定外の構造は無視/ベストエフォートで拾い、他を巻き込まない。
- **欠落ゼロ**: 変更行（数値・記述式）を取りこぼさない。
- **誤帰属ゼロ**: ある対象の変更が別対象に混入しない（コーキ/アジール型の誤りが11パッチのどこにも無い）。
- **中間ラベル対応（残課題2）**: ブロック内の `<p><strong>個別名</strong></p>`（h3/h4でない個別見出し。オーグメント名・サブ項目名等）を検出し、以降の変更をその個別名のグループ/サブ対象に紐づける（1グループに潰さない）。逐語維持。

### F-S7-2: 対象名の文脈解決（残課題1）
- h3が無いブロックで対象名を決める際、**セクション種別を考慮**する。「チャンピオン」セクション以外（システム/アリーナ/ルーン/オーグメント/バグ修正/エピックオブジェクト等）では、先頭h4や中間ラベルを対象名に使っても「チャンピオン」という誤解を招く総称にしない。可能な限り**具体的な対象名**（例: アリーナ→そのオーグメント名やサブ見出し、システム→「ブルーバフ」等の個別名）を出す。適切な個別名が無い場合はセクション名そのもの（例「エピック オブジェクトの調整」）を対象名にする。
- チャンピオン対象（アイコンが champion/、またはチャンピオンセクション内でh3あり）は従来どおり誤帰属ゼロを維持。

### F-S7-3: kind/セクション分類の拡充
- 大型26.1で現れるセクション（ロールクエスト/エピックオブジェクト/ジャングル/タワー/ミニオン/新アイテム/復活するアイテム/アップデートされたアイテム/オムニヴァンプ/メイヘム 等）を、`targetKind`（champion/item/rune/system/arena/bugfix/other）に妥当に分類する。判定できないものは `other`／`system` に安全に寄せる（崩さない）。
- アイテム系セクション（新アイテム/復活するアイテム/アップデートされたアイテム）は item として扱い、アイコン・価格の既存処理に乗せる。

### F-S7-4: フィクスチャ整備とテスト網羅
- **フル11パッチHTML（`__fixtures__/patches/`）はコミットしない**（合計3MB超で重い）。generatorはこれらを分析・テストに使い、**各パッチから構造の多様性を代表するブロックを抜粋した軽量フィクスチャ**を `__fixtures__/` に整備する（S6の既存フィクスチャを拡充）。抜粋には少なくとも: 大型26.1のシステム系セクション代表・アリーナのオーグメント個別名・ルーン・新/復活/更新アイテム・前シーズン25系の代表・記述式/数値の両変更 を含める。**作業後 `__fixtures__/patches/` は削除**する（git status で消えていること）。
- 11パッチを実際にパースして「例外ゼロ・対象数/変更数が妥当・誤帰属ゼロ」を確認するスモークテスト（フル版は使うがコミットしない形。抜粋フィクスチャでの決定的テストを主とする）。

## 制約・非目標
- **AIは使わない**（DOMパース/分類/表示は純ルール）。**逐語維持・捏造禁止**。
- 反応記事/翻訳/SEO/他ソース・fact/summaryモード・S4のLoLデザインは不変。DOM失敗時フォールバック維持。
- **フル11パッチHTMLはコミットしない**（抜粋フィクスチャのみ）。DBスキーマ変更なし・新規npm依存なし（軽量HTMLパーサを足す場合のみ npm audit 確認）。
- 未適用/速報経路（S5）は本スプリントでは扱わない。

## テスト（必須・実データ抜粋フィクスチャ・実ネット非依存）
1. 11パッチすべてを `parsePatchNotesHtml` に通して**例外が出ない**・各パッチで対象/変更が0件でない（欠落していない）ことを確認。
2. **誤帰属ゼロ**（S6の既存: アジール=W/R記述式・コーキ=base/R を維持）＋大型26.1で各対象の変更が正しい対象に付く（サンプル抽出して検証）。
3. **アリーナ対象名**が「チャンピオン」にならず、オーグメント個別名/サブ見出し/セクション名など妥当な名前になる。
4. **中間ラベル**（`<p><strong>個別名</strong></p>`）が検出され、以降の変更がその個別名に紐づく（1グループに潰れない）。
5. 大型26.1のシステム系セクション（ロールクエスト/エピックオブジェクト/新アイテム等）が対象名付きで崩れず出る。前シーズン25系も崩れない。
6. 逐語一致（stat/before/after/text が実HTMLの文字と一致）。既存の parser/compose/article-body-view/seo/search テストが回帰しない。

## 受け入れ基準
1. `npx vitest run` 全Green・`npx tsc --noEmit`・`npm run build`・`npm run lint` 通過。
2. 11パッチ（大型26.1・前シーズン25系含む）すべてで、例外ゼロ・欠落ゼロ・誤帰属ゼロ・崩れゼロ。アリーナ対象名とオーグメント個別名が妥当に解決される。
3. AI不使用・逐語維持・DBスキーマ変更なし・新規依存なし・S4デザイン不変。フル11パッチHTMLはコミットしない。

## 評価基準（evaluator向け）
- テスト全Green・build/tsc/lint通過・コンソールエラー0。
- 11パッチ抜粋フィクスチャで全構造パターンが欠落/誤帰属/崩れなく抽出される。大型26.1で破綻しない。アリーナ対象名・中間ラベルが改善されている。逐語維持。
- 受け入れ基準1〜3を満たす。
