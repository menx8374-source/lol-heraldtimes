# admincms-S1 — 公開ポリシー基盤とレビューキュー（要レビュー状態の導入）

運営CMS v2 の起点スプリント。仕様書 `docs/spec/admin-cms-v2-spec.md` の **Sprint 1**（F1〜F4）を実装する。

## 含まれる機能（F1〜F4・仕様書原文の要点）
- **F1 カテゴリ別 公開ポリシー設定**: 管理画面でカテゴリごとに「自動公開/要レビュー」をトグル。DB保存で再起動後も保持。既定=全カテゴリ「要レビュー」。
- **F2 「要レビュー」記事状態とレビューキュー**: 記事状態に「要レビュー」を追加。その状態の記事は公開サイトに一切出さない。`/admin`のレビューキューに一覧し「承認して公開/却下/編集・プレビュー」。承認/却下の操作は既存の保留キューのパターンを踏襲。held/rejected/scheduled/publishedの意味は不変。
- **F3 パイプラインの公開ポリシー尊重**: 自動収集パイプラインが記事化時にカテゴリのポリシーを参照。自動公開→従来どおり公開、要レビュー→公開せず要レビューで保存。安全フィルタ保留(held)はポリシーより優先。実行ログに要レビュー件数も分かる形で記録。
- **F4 管理画面プレビュー**: 要レビュー記事を公開ページと同じ体裁で`/admin`配下から確認。プレビューしても公開状態にならない。Basic認証内・robots除外。

## 受け入れ基準（仕様書 Sprint 1 原文・このスプリント終了時にデモできる状態）
- [ ] `/admin` を開くと、ページ上部に「未レビュー N件」のバッジが表示される。
- [ ] `/admin` に「公開ポリシー」パネルがあり、6カテゴリ（5chの反応／海外の反応／Xの反応／パッチ/メタ／Riot公式／eスポーツ）が1行ずつ並び、初期状態では全行が「要レビュー」と表示される。
- [ ] 「パッチ/メタ」の行を「自動公開」に切り替えて保存すると、その行だけが「自動公開」と表示され、他5行は「要レビュー」のまま変わらない。ブラウザを再読み込みしても同じ表示になる。
- [ ] アプリを停止して再起動し `/admin` を開き直しても、「パッチ/メタ＝自動公開、他＝要レビュー」の設定が保持されている。
- [ ] 「パッチ/メタ」を「要レビュー」に戻して保存すると全カテゴリが「要レビュー」に戻り、再読み込み後も保持される。
- [ ] 全カテゴリ「要レビュー」の状態でパイプラインを1回実行すると、公開記事の総数が実行前と変わらず、生成された記事が「レビューキュー（要レビュー）」セクションにタイトル・カテゴリ・生成日時・出典リンク付きで新しい順に並ぶ。
- [ ] 「パッチ/メタ」だけ「自動公開」にしてパイプラインを1回実行すると、パッチ/メタの記事は公開記事として増えてトップ一覧に現れ、それ以外のカテゴリの記事はレビューキューに積まれる。
- [ ] 安全フィルタに引っかかる記事は、そのカテゴリが「自動公開」でも公開されず、既存の「保留キュー」に理由付きで入る（レビューキューには入らない）。
- [ ] レビューキューの記事の個別記事 URL（スラッグ）を直接ブラウザで開くと、記事本文が表示されず 404 相当のページになる。
- [ ] レビューキューの記事のタイトルに含まれる語で公開サイトの検索を実行しても、その記事がヒットしない。
- [ ] レビューキューの記事が、トップ一覧・当該カテゴリ一覧・タグ一覧・アーカイブ・人気ランキング・関連記事・サイトマップのいずれにも現れない（それぞれの画面／出力を開いて確認できる）。
- [ ] レビューキューの記事の「プレビュー」を押すと `/admin` 配下のプレビュー画面が開き、タイトル・カテゴリ・タグ・サムネイル・本文の全ブロックが公開記事ページと同じ構造（見出し／段落／引用／レス枠／埋め込みカード／パッチ表／目次）で表示される。レス番号・名前・強調色・アンカーの見え方も公開ページと一致する。
- [ ] プレビュー画面を開いた後にレビューキューへ戻ると、その記事はまだレビューキューに残っている（プレビューで公開されない）。
- [ ] プレビュー画面に認証なしでアクセスすると Basic 認証を要求され、検索エンジン非インデックス指定がページに含まれる。
- [ ] レビューキューの記事に「承認して公開」を押すと、その記事がレビューキューから消え、未レビュー件数が1減り、公開サイトのトップ一覧に現れる。
- [ ] レビューキューの記事に「却下」を押すと、その記事がレビューキューから消え、公開サイトのどこにも現れない。
- [ ] 既存の「保留キュー」「保留コメント」「記事管理（編集リンク／ピン留め／予約解除）」「直近の実行結果」「公開記事総数」「人気記事」「エラー／失敗ログ」の各セクションが従来どおり表示され、保留記事の「承認して公開」「却下」「予約公開に設定」が従来どおり動作する。
- [ ] 記事管理セクションの状態ラベルに「要レビュー」が加わり、既存の「公開中／保留中／却下済み／予約公開待ち」と区別して表示される。
- [ ] 予約公開に設定済みの記事が、予約時刻の到来後のパイプライン実行で従来どおり公開される（要レビューに差し戻されない）。
- [ ] レビューキューが0件のとき「要レビューの記事はありません」と表示され、バッジが「未レビュー 0件」になる。
- [ ] ポリシー設定・承認・却下の各操作を Basic 認証を通さずに直接実行しても、設定・記事状態が変更されない。

## テスト観点（自動テストを書く対象・原文）
- カテゴリ別ポリシーの読み書き: 未保存時の既定値（全カテゴリ要レビュー）、1カテゴリだけ変更したときの他カテゴリ不変、未知のカテゴリ名を渡したときの扱い。
- 公開可否の判定ロジック: （安全フィルタ不通過, ポリシー自動公開）→保留、（通過, 自動公開）→公開、（通過, 要レビュー）→要レビュー、の分岐を入出力で網羅。
- 公開系クエリの絞り込み: 要レビュー状態の記事が一覧・検索・ランキング・関連記事・サイトマップの取得結果に含まれないこと（既存4状態の挙動が変わらないことも併せて）。
- 状態遷移: 要レビュー→公開、要レビュー→却下、保留→公開（既存）、予約→公開（既存）が期待どおりに遷移し、それ以外の不正な遷移を受け付けないこと。

## 実装ガイド（既存コードとの結線・オーケストレーターより。architectは再実行しないため方針を明示）
- **要レビュー状態の持ち方**: `Article.status` に新しい値 **`"review"`**（要レビュー）を追加する（enumはString運用。既存 published/held/rejected/scheduled の意味・heldReason等は不変）。**public/閲覧系クエリが `status === "published"` で絞っていることを全経路で確認**し、`review` が漏れないことを保証する（万一 `status != "held"` 等の否定形絞り込みがあれば `=== "published"` に是正）。対象は少なくとも: 一覧(home/category/tag/archive)・検索・人気ランキング・関連記事(related-articles)・サイトマップ/news-sitemap・RSS/feed・個別記事ページ(slug)・OGP/JSON-LD。個別URL直叩きは公開記事と同様に404相当(notFound)にする。
- **カテゴリ別ポリシーの保存**: 再起動後も保持が要件のためDB永続化する。既存スキーマに無いので新規モデルを1つ追加してよい（例 `CategoryPublishPolicy { category String @unique, autoPublish Boolean, updatedAt }`）。未登録カテゴリは既定=要レビュー(autoPublish=false)として読む純関数を用意。Prisma migrate/generate を実行。
- **パイプラインのポリシー分岐**: 記事の公開状態を決めている箇所（post-pipeline の生成→moderation→公開ステータス確定。既存で published/held を決めているところ）に分岐を追加。判定は純関数に切り出す: `decidePublishState({ moderationHeld, autoPublish }) => "held" | "published" | "review"`（held優先）。要レビューで保存した件数を `PipelineRunLog` 等の実行サマリ／既存ログに載せる（既存の publishedCount/heldCount に **reviewCount 相当**を追加。スキーマ追加が要るなら最小限で）。
- **承認/却下**: 既存 `src/app/admin/actions.ts` の approve/reject パターンを踏襲。承認は `status="published"`＋`publishedAt`設定＋**既存の一覧再検証 `revalidatePublishedListings`（機能B）を呼ぶ**。却下は既存 rejected と同様（`status="rejected"`）。レビューキューの取得は `src/lib/admin/articles-admin.ts` 等に `listReviewQueue()` を追加。
- **プレビュー**: 公開記事詳細で本文を描画している既存コンポーネント（`src/components/article-body-view.tsx` 等）を `/admin/articles/[id]/preview` から再利用し、公開ページと同一体裁にする。`export const metadata = { robots:{index:false,follow:false} }`＋`dynamic="force-dynamic"`。プレビューは状態を変更しない（GET相当）。
- **バッジ/レビューキューUI**: `src/app/admin/page.tsx` に「未レビュー N件」バッジ・「公開ポリシー」パネル・「レビューキュー（要レビュー）」セクションを追加（既存セクション構成・スタイルに合わせる）。ポリシートグルはserver action。

## 制約・非目標
- 公開サイト（閲覧者向け）の見た目・導線は変更しない（唯一の観測変化=要レビュー記事が公開側に一切出ない・承認で即反映）。
- 既存4状態(published/held/rejected/scheduled)・保留キュー・保留コメント・予約公開・ピン留めの挙動は不変。
- 手動記事化(S2)・フル構造エディタ(S3/S4)・公開後編集の即時反映の運用効率化(S5)は本スプリント対象外。プレビューは本文描画の再利用のみ（編集UIはS3）。
- 新規依存は最小限（できれば無し）。テスト必須（上記テスト観点）。architectのベースライン(Next.js/Prisma/SQLite/Vitest)不変。
- READMEに管理者向けの新運用（公開ポリシー・レビューキュー）を最小限追記。
