# パッチ刷新S5 — 未適用パッチの速報＋本番反映後の自動確定（opt-in・デフォルト無効・スキーマ変更なし）

`docs/patch-accuracy-research.md` §2.5。公式パッチノートは**本番反映前に公開される**ため、未適用の段階で先行記事化（速報＝QDFでPVを取る）し、本番反映後に同じ記事を確定版へ自動更新する。
**AI不使用**。**必ず opt-in（env で無効時は既存挙動を1バイトも変えない）**。対象: Web。

## 背景（research §2.5・実測）
- DDragonは本番リリース済みバージョンのみ（versions.json先頭＝現行live）。公式パッチノートHTMLは反映前に公開される（S1〜S7のDOMパーサは反映前でも同じ構造で正確に抽出できる＝DDragon非依存）。
- 現状のriot-datadragon収集は「versions.jsonの現行live版」を前提にパッチ記事化する（＝本番反映済みのみ）。S5では**opt-in**で「次パッチ（未適用）のノートが公開されていれば先行記事化」を足す。
- **最重要制約**: env が無効（既定）なら現状と完全同一。DBスキーマは変更しない（patchStageは記事本文のバッジブロックで表現し、既存の記事更新機構で差し替える）。

## 含まれる機能

### F-S5-1: 未適用パッチの検知（opt-in・riot-datadragon.ts）
- env `PATCH_PREVIEW_MODE`（既定 `off`＝無効）。`on` のときのみ以下を行う。`off` では収集・記事化は**現状と完全同一**。
- 現行live版（versions.json先頭）から**次のパッチ番号**を算出し（既存の `publicPatchNumber` 系ロジックを使い、minorを+1）、`buildPatchNoteUrl(次パッチ)` が **200 で本文が取得できるか**を確認する。取得できれば「未適用パッチのノートが公開済み」＝preview対象。取得失敗（404/未公開）なら何もしない（現状どおり現行live版のみ）。
- URL形式は世代で異なる（S7で判明: 新しい世代は `league-of-legends-patch-<major>-<minor>-notes`）。次パッチは新形式で試す。失敗時は例外を投げず現状にフォールバック（本体を止めない）。

### F-S5-2: preview記事化（速報バッジ）
- 未適用パッチのノートを S1〜S7 の `parsePatchNotesHtml`→`composeDetailedPatchBody`（DOM経路）で本文化し、`externalId = 次パッチ番号`（例 "26.15"）でPost/記事化する（既存のパッチ記事化と同じ経路。免除ソースriotとして扱う）。
- 記事本文の先頭に**速報バッジブロック**を入れる（既存の `ArticleBodyBlock`。専用の paragraph か既存の注意喚起ブロックを流用）: 例「【速報・未適用】このパッチはまだ本番環境に適用されていません。適用後に内容が変更される場合があります（公式のPBE/公開情報に基づく先行速報）」。**捏造しない**（公式ノートの逐語＋この注意書きのみ）。
- タイトルにも先行性が伝わる接頭辞（例「【速報】」）を付けてよい（既存のパッチタイトル生成の範囲で・任意）。
- CDragon PBE の数値補完は**任意・非目標**（今回は公式HTMLの逐語のみで速報化。数値の空欄はそのまま）。

### F-S5-3: 本番反映後の自動確定（既存の記事更新機構を流用）
- versions.json 先頭が当該パッチ番号に更新された（＝本番反映）ことを検知したら、**同 `externalId` のpreview記事を確定版へ更新**する: 速報バッジを外し、（必要なら）公式HTMLを再取得して本文を最新化（hotfixで改訂される場合に対応）。
- 更新は既存の記事更新機構（`generate-article` 周辺・`ArticleUpdateHistory`・Post再生成）を流用し、**同一記事を差し替える（重複記事を作らない）**。`externalId=パッチ番号` で一意特定。
- DBスキーマは変更しない。patchStage（preview/live）は「速報バッジブロックの有無」で表現する（バッジがあればpreview、外れていればlive確定）。

## 制約・非目標
- **opt-in厳守**: `PATCH_PREVIEW_MODE` 未設定/`off` では収集・記事化・表示すべて現状と**完全同一**（回帰ゼロ）。
- **AIは使わない**（検知・記事化・更新は純ルール／既存経路）。**逐語維持・捏造禁止**（速報でも公式ノートの逐語のみ。未確定を「確定」と偽らない・速報バッジで明示）。
- **DBスキーマ変更なし・新規npm依存なし**。反応記事/翻訳/SEO/他ソース・fact/summaryモードは不変。
- CDragon PBE数値補完・カレンダートリガは非目標（将来）。preview記事は「公式ノート公開後・本番反映前」を対象とし、PBEのみ（公式ノート未公開）の段階は対象外でよい。
- 秘密なし（新env `PATCH_PREVIEW_MODE` は秘密でない。`.env.example` にキー名と既定offを明記）。

## テスト（必須・実ネット非依存・実HTTPは叩かない）
1. **opt-in無効（既定）で回帰ゼロ**: `PATCH_PREVIEW_MODE` 未設定時、収集・記事化が現状と完全同一（未適用検知ロジックが走らない）。
2. 未適用検知: `on` かつ次パッチノートが200のとき preview対象になる。404/取得失敗時は現状フォールバック（例外を投げない）。fetchはモック。
3. preview記事化: 速報バッジブロックが本文先頭に入り、本文はS1〜S7のDOM抽出で正確（誤帰属ゼロ・逐語）。externalId=次パッチ番号。
4. 自動確定: versions.json先頭が当該パッチに更新されたら、同externalIdの記事が確定版に更新され速報バッジが外れる。重複記事を作らない。
5. 既存の riot-datadragon/compose/パイプライン/記事更新 テストが回帰しない。

## 受け入れ基準
1. `npx vitest run` 全Green・`npx tsc --noEmit`・`npm run build`・`npm run lint` 通過。
2. `PATCH_PREVIEW_MODE=on` で未適用パッチが速報バッジ付きで先行記事化され、本番反映後に同一記事が確定版へ自動更新される（重複なし）。`off`/未設定では現状と完全同一（回帰ゼロ）。
3. AI不使用・逐語維持・捏造なし（速報は明示）・DBスキーマ変更なし・新規依存なし・秘密なし。

## 評価基準（evaluator向け）
- テスト全Green・build/tsc/lint通過・コンソールエラー0。
- opt-in無効で既存挙動が完全維持される（回帰ゼロ）。有効時に未適用検知→preview記事化(速報バッジ)→本番反映後の確定版更新(重複なし)がテストで確認できる。逐語維持・誤帰属ゼロ。
- 受け入れ基準1〜3を満たす。
