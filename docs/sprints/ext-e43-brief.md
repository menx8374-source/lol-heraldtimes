# 拡張E43 — 反応記事のレス選定を話題一貫に（無関係レスの混入を解消）

運用フィードバック起点。対象: Web。

## 背景（なぜ・現象）
反応記事（5ch）で、タイトル（例「ソロキュー拮抗試合のモチベーション維持」）や主要レス（58/61）と**全く関係のないレス**が
混入していた: 別話題のガンク論(38)、別チャンピオンのバランス雑談(65/70)、WASD移動システムの脱線(75/76/81)、
無関係な質問(413「midでベイガーみたいなAP誰かおらん？」/738「jg上手くなりたい、いい配信者は？」)。

原因（推定）:
- 5chスレは**複数の話題に脱線**しており（E39で盛り上がったレスを拾うが話題は問わない）、
- LLMの話題関連レス選定（`selectReactionReses`）が**うまく選べず null を返す**と、`buildReactionBlocks` の
  フォールバックが**収集した全レスをそのまま表示**する（＝話題バラバラのレスが昇順で全部出る）。
- 実際の記事も 38,58,61,65,70,75,76,81,413,738 と昇順で並んでおり「全レス表示フォールバック」の兆候。

## 含まれる機能

### F-E43-1: レス選定LLMプロンプトを「単一の中心話題に一貫」させる（compose.ts `selectReactionReses`）
- system指示を強化し、次を明確に要求する:
  - スレは複数の話題に脱線していることが多い。**最も反応・議論が集まっている1つの中心的な話題に絞り**、
    それに沿ったレスだけを選ぶ。
  - **中心話題に無関係なレスは必ず除外する**: 別の話題への脱線、別チャンピオン/別ゲームシステムの雑談、
    独立した別の質問（「〜のおすすめは？」「〜って誰かいる？」等）、テンプレ・運営文。
  - 互いに `>>N` で参照し合って**会話としてつながっているレスを優先**する（文脈が通る）。
  - 無理に多く選ばない（少数でも一貫している方が良い）。レス本文は書き換えず index を選ぶだけ（従来どおり）。
- 出力JSON形式・keep/emphasize/color の仕様は現状維持（E32/E36）。

### F-E43-2: 選定失敗時のフォールバックを「全レス」から「主要な会話クラスタ」に変える（compose.ts `buildReactionBlocks`）
- 現在: `selection` が null（LLM失敗・mock・parse不能・keep空）のとき `selectedIndices = 全レス`（無制限）。
  → これが「無関係レス全部出る」の直接原因。
- 変更: 純関数で**アンカー（`>>N`）で連結した会話クラスタ（連結成分）**を求め、**最大のクラスタ**（＝そのスレで
  最も会話が集まっている中心的な議論）を採用する:
  - 各レスの `>>N` を双方向の辺として連結成分（union-find/BFS）を作る（`extractAnchors` 再利用、存在する番号のみ）。
  - **最大サイズの連結成分**を選ぶ。同サイズは「被参照合計が多い→レス番号が小さい」順で決定論的に決める。
  - 採用レスは元スレ順（レス番号昇順）で、`MAX_EXCERPT_RESES`(12) を上限に。
  - 連結成分が全て1件（会話が無い＝アンカーが無いスレ）の場合のみ、最後の保険として従来どおり全レス（ただし
    `MAX_EXCERPT_RESES` で上限を付ける）にフォールバックする。
- これにより、LLM選定が失敗しても**別話題の独立レス（無関係な質問・脱線）は落ち、中心的な会話だけが残る**。
- 既存の「LLM選定が成功したら keep のレスを使う」経路は変えない（成功時は強化プロンプトで一貫選定される）。
- E41のアンカー先文脈引用は従来どおり最終選定集合に適用（クラスタは既にアンカー閉包なので追加は基本発生しない）。

## 制約・非目標
- 逐語維持（レス本文は書き換えない。選定・並べ替えのみ）。新規npm依存なし。LLM呼び出し回数は増やさない。
- パッチ/clip・NG・強調色・サムネ・5ch収集・タイトル生成には触れない（レス選定の一貫性のみ）。
- mock既定は「LLM選定 null → フォールバック」経路を通るため、フォールバックの挙動変更が mock 記事にも及ぶ
  （全レス→主要クラスタ）。既存テストは新仕様に更新する（回帰ではなく意図した改善）。

## テスト（必須・実API/実ネット非依存）
1. F-E43-2 純関数（クラスタ選定）: 複数の会話クラスタ＋独立レスを含むスレで、最大クラスタのレスだけが選ばれ、
   独立した無関係レス（アンカー無し）や小さいクラスタが除外される。同サイズは決定論的タイブレーク。上限が効く。
   アンカーが全く無いスレは全レス（上限付き）。
2. F-E43-2 `buildReactionBlocks`: `selectReactionReses` が null を返すケース（mock/スタブ）で、全レスではなく
   主要クラスタのレスだけがブロック化される。E41のアンカー先引用が壊れない。
3. F-E43-1: 強化した system プロンプトに「単一中心話題・無関係レス除外・会話つながり優先」の指示が含まれる
   （文字列/構造の確認で可）。LLM選定が成功した場合は keep のレスが使われる（回帰なし）。
4. 既存の compose/reaction/pipeline テストが新仕様（フォールバック＝主要クラスタ）に沿って回帰しない。

## 受け入れ基準
1. `npx vitest run` 全Green（新規/更新含む・実API/実ネット非依存）。
2. `npx tsc --noEmit`・`npm run build`・`npm run lint` 通過。
3. 反応記事に、中心話題と無関係な独立レス（別質問・別話題の脱線）が混入しにくくなる（LLM成功時は一貫選定、
   失敗時も主要な会話クラスタのみ）。逐語維持・新規依存なし・LLM呼び出し増なし。

## 評価基準（evaluator向け）
- テストGreen・build/tsc/lint通過。mock/生成パイプラインが回帰しない（コンソールエラー0で反応記事が表示）。
- クラスタ選定フォールバックとプロンプト強化がテストで確認できる。
- 受け入れ基準1〜3を満たす。
