# 拡張E25 ブリーフ — 反応記事のレス抜粋（話題に関係するもののみ）＋重要レスの強調

運用フィードバック起点の機能追加。E24（LLM本接続）の上に構築する。対象プラットフォーム: Web。

## 背景（なぜ）
- おばにゅー流のまとめは「スレの全レスを羅列」せず、**記事の話題に関係するレスだけを抜粋**し、**重要なレスは文字を大きく/目立たせて**掲載する。
- 現状の反応記事(reddit/5ch)は `buildReactionBlocks`(compose.ts)が**スレの全レスを逐語で羅列**しており、無関係な雑談も混ざる。
- E24でLLM本接続が入ったので、その `LLMClient` を使って「どのレスを載せるか（抜粋）」「どれを強調するか」の**編集判断**をLLMに委ねる。**レス本文は逐語のまま**（LLMに書き換えさせない。選定と強調フラグだけを使う）。

## 含まれる機能

### F-E25-1: LLMによる「話題に関係するレスの抜粋」
- 対象: `src/lib/generation/compose.ts` の反応系ボディ組み立て（`composeReactionBody`/`buildReactionBlocks`）と、必要なら `src/lib/generation/generate-article.ts`（llmClientを渡す配線）。
- 反応記事の生成時、パース済みレス群（`parseThreadReses` 等が返すレス配列。番号・名前・本文を持つ）を、記事タイトル/話題とともにLLMへ渡し、「**話題に関係する重要なレスのインデックス（0始まり等、実装に合わせる）**」と「**そのうち特に強調すべきレスのインデックス**」を返させる。
  - LLMClient は `generate(messages): Promise<string>` なので、**JSONを出力させて防御的にparse**する（例: `{ "keep": [i,...], "emphasize": [i,...] }`）。system指示に「本文は書き換えず、渡したレスの中から選ぶだけ」「JSONのみ出力」を明記。
  - **必ず検証**: 返ったインデックスは実在範囲(0〜レス数-1)に限定し、重複除去。`emphasize` は `keep` の部分集合に丸める。1記事あたり抜粋上限（例 最大12件）を設け、超過分は先頭優先で切る。
  - 選定後、**元のレス配列から該当インデックスのレスを逐語のまま**取り出して反応ブロックを組む（順序は元スレ順を維持）。
- **フォールバック（本体を止めない）**: mockモード・APIエラー・JSON parse失敗・keepが空/全て不正 の場合は、**従来どおり全レス（既存の上限があればそれ）を強調なしで**組む。例外を投げない。

### F-E25-2: 重要レスの強調表示
- 対象: `src/lib/article-body.ts`（`ArticleBodyReactionBlock` 型）と `src/components/article-body-view.tsx`（反応ブロックの描画）。
- 反応ブロックに **レス単位の強調フラグ**（例 `emphasis?: boolean` もしくは既存の行単位 emphasis と整合する形）を追加できるようにし、F-E25-1でLLMが `emphasize` に選んだレスに立てる。
- 描画: 強調レスは**文字を大きく＋太字**（例 `text-base sm:text-lg font-bold`）等で目立たせる。非強調レスは従来の見た目。色は既存のダーク/ライト・design切替と整合させる（新規CSS変数は増やさず既存トークン/クラスで）。
- 既存の行単位 emphasis("red"/"orange") とは併存してよい（役割が違う）。パース/表示の後方互換を壊さない（emphasisフラグは任意で、無ければ従来表示）。

## 制約・非目標
- **逐語転載を維持**: LLMにレス本文を書き換え・要約させない。使うのは「選定インデックス」と「強調インデックス」だけ。
- riot(パッチ検知)記事・clip記事・タイトル生成(E24)には手を触れない。
- mockモード（既定・APIキー無し）では**従来と完全に同じ**挙動（全レス・強調なし）。コスト0。
- LLM呼び出しは1記事あたり1回（抜粋＋強調をまとめて取得）。Haiku・`max_tokens`控えめ。
- シークレット・依存は増やさない（E24の @anthropic-ai/sdk を使う）。

## テスト（必須・TDD-lite、実API非依存）
- `LLMClient` をスタブ化し、JSON選定応答を返すfakeで検証:
  1. LLMが `{keep:[...], emphasize:[...]}` を返したとき、**keepのレスだけが逐語で**反応ブロックに出て、emphasizeのレスに強調フラグが立つ。
  2. 範囲外・重複・emphasize⊄keep のインデックスが**正規化**される（実在範囲・keep部分集合・上限）。
  3. JSON parse失敗・空keep・例外・mockモードのとき、**全レス・強調なし**にフォールバックし例外が外に漏れない。
  4. 反応ブロックの表示テスト（article-body-view）: emphasisフラグ付きレスが強調クラスで描画され、無しは従来クラス。
  5. 既存の反応記事・compose・generate-article のテストが回帰しない（mock時は従来出力）。

## 受け入れ基準
1. `npx vitest run` 全Green（新規テスト含む・実API非依存）。
2. `npx tsc --noEmit`・`npm run build`・`npm run lint` 通過。
3. mock既定・APIキー無しで従来どおり（全レス・強調なし・コスト0・回帰なし）。
4. liveスタブで、話題に関係するレスのみ抜粋＋重要レス強調の配線が動く（テストで検証、実API非依存）。
5. 逐語転載維持（LLMはレス本文を書き換えない）。新規依存なし。

## 評価基準（evaluator向け）
- テストGreen（実API非依存）。build/tsc/lint通過。
- 実機(mock)でトップ/記事詳細がコンソールエラー0で表示、反応記事が従来どおり出る（回帰なし）。
- 強調レスの描画が視認できる（emphasisフラグ付きモックデータ or テストで確認）。
- 受け入れ基準1〜5を満たす。
