# 拡張E28 — レス選定の厳選化＋長レスのレス内文抽出（記事内容に沿った部分だけ掲載）

E25/E26のLLMレス選定を発展させる編集強化。対象: Web。E24で入ったLLM本接続(Haiku)を使う。

## 背景（なぜ）
- 運用フィードバック: 反応記事が「レス1〜16をそのまま羅列」になりがち。おばにゅー流に、
  (1) **記事の話題に関係するレスだけ**を厳選し、(2) **長いレスは記事内容に沿った文（行）だけ**を抜粋したい。
- 現状 `compose.ts` の `selectReactionReses` は「keepするレスのindex」だけをLLMに返させ、選んだレスは
  **行(lines)を丸ごと**採用している。ルール文・テンプレ・雑談レスも混じり、長レスも全文載る。
- 逐語転載は維持する（LLMに本文を書き換えさせない。使うのは「どのレス/どの行を残すか」のindexのみ）。

## 含まれる機能

### F-E28-1: レス選定プロンプトの厳選化
- `selectReactionReses` のsystem指示を強化し、次を明示する:
  - スレのルール文・テンプレ（"!extend"・"次スレは>>950"・"配信者やプロの話題禁止"等の定型/運営文）、
    単なる雑談、記事の話題に無関係なレスは**除外**する。
  - 記事の話題の**中心となる反応・意見・議論・感想**のあるレスだけを厳選する（無理に多く選ばない）。
- 上限(MAX_EXCERPT_RESES=12)・「本文は書き換えず選ぶだけ」は維持。

### F-E28-2: 長レスの「レス内の文（行）抽出」
- LLMに渡すタスク(`reaction-select`)の各レスを、`text`(結合文字列)ではなく **`lines: string[]`（行配列）** で渡し、
  LLMが**残す行のindex**を指定できるようにする。
- LLMの返却JSONを拡張して受け付ける（後方互換）:
  - `keep` の各要素は **`number`（レスindex、行は全採用）** または **`{ "index": N, "lines": [行index,...] }`（そのレスで残す行だけ）** のどちらでもよい。
  - `emphasize` は従来どおりレスindexの配列（keepに含まれるものに丸める）。
- `normalizeReactionSelection` を、keep要素が number/オブジェクトどちらでも扱えるよう拡張:
  - レスindexは範囲内・整数・重複除去・上限12。
  - `lines` があればそのレスの行数範囲内の整数のみ・重複除去・元順維持。空や全て不正なら「そのレスは全行採用」に丸める。
  - `emphasize` は採用レスindexの部分集合に丸める。
  - 全keepが不正なら null（呼び出し側が全レス・全行・強調なしにフォールバック）。
- `buildReactionBlocks`: 採用レスごとに、`lines`指定があれば **元の `res.lines` からそのindexの行だけを逐語のまま**採用する（指定なしは全行）。行の強調(computeLineEmphasis)・アンカー(extractAnchors)・NG伏字(maskNgWords, 拡張E27)は**抽出後の行**に対して整合的に適用する。

## 制約・非目標
- 逐語転載を維持（LLMはレス本文/行を書き換えず、残すindexのみ指定）。抜粋した行は元テキストのまま。
- mockモード（既定・APIキー無し）は従来どおり全レス・全行・強調なし（回帰なし・コスト0）。`MockLLMClient` の
  `reaction-select` 応答は従来の「全keep・emphasize空」を維持（lines指定なし＝全行）。
- LLM呼び出しは1記事1回。新規依存なし。riot/clip・タイトル生成には触れない。NG伏字(E27)の挙動は維持。

## テスト（必須・実API非依存、LLMはスタブ）
1. `keep=[{index:1,lines:[0,2]}]` のとき、レス2の**0行目と2行目だけ**が逐語で残る（1行目は落ちる）。
2. `keep=[1]`（数値・後方互換）のとき、レス2の**全行**が残る。
3. `lines` に範囲外/重複/全不正が含まれるとき正規化される（範囲外無視・全不正なら全行）。
4. 厳選プロンプトでも、mock（全keep）時は従来どおり全レス・全行（回帰なし）。
5. 抽出後の行にNG伏字(E27)・行強調・アンカーが整合的に効く。
6. 既存のE25/E26/E27テストが回帰しない。

## 受け入れ基準
1. `npx vitest run` 全Green（新規含む・実API非依存）。
2. `npx tsc --noEmit`・`npm run build`・`npm run lint` 通過。
3. LLMが `{index, lines}` を返すと長レスの指定行だけが逐語で残り、数値keepや未指定は全行（後方互換）。
4. mock既定で従来どおり（回帰なし・コスト0）。逐語維持。新規依存なし。
