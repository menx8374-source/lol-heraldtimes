# PBE-S5 — XツイートをPBE記事に統合（スキル数値を出典付き埋め込み・未確定・人手キュレーション枠）

PBE-S3で取得した Spideraxe/Phroxzon のツイート（スキル数値を含む・多くは画像）を、PBE記事に**出典付きで埋め込み/引用**して統合する。
これにより「PBEでスキルのダメージ・レシオも」を、**数値を機械再構成せず出典そのままで**＝誤情報ゼロで実現する。**AI不使用・opt-in（既定off）・コスト安全設計**。対象: Web。

## 背景
- CDragonでは正確なスキル数値を機械抽出できない（ツールチップ未解決・effectAmountsラベル無し）。→ スキル数値は **Spideraxe氏のX投稿を出典として埋め込み/引用**する（本人の数値そのまま＝誤情報にならない）。
- PBE-S4 で CDragon自動分（アイテム・基本ステータス・cost/cooldown・日本語スキル名）のPBE記事が既にある。PBE-S5 はそこに**「PBEのスキル変更（データマイナー情報・未確定）」セクション**を足す。
- ユーザー合意: 網羅性優先の**半自動**（画像内数値は必要に応じ人手キュレーション）。

## 含まれる機能

### F-PBE5-1: X取得の配線（opt-in・コスト安全設計）
- `pbe-article.ts`（PBE-S4）で `PBE_ARTICLE_MODE=on` の生成時に、**追加条件を全て満たすときだけ** `pbe-x-source.fetchPbeSourceTweets()` を呼ぶ:
  - `X_API_KEY` が設定されている（未設定ならX取得はスキップ＝CDragon自動分のみ・$0）
  - `pbe版 ≠ latest版`（PBE窓＝新パッチ準備中）
  - **レート制限**: 前回X取得から一定間隔（env `PBE_X_MIN_INTERVAL_HOURS`、既定 6h 等）を空ける（毎回叩かない。最終取得時刻は既存の状態保存 or Post/媒体で管理。無ければ簡易に最小実装）。
- これによりX API課金は「PBE窓中・キーあり・レート内」だけ＝月数十円〜$1未満に収まる。取得失敗は空で本体を止めない。

### F-PBE5-2: PBE記事へのツイート統合（埋め込み/引用・出典・未確定）
- `pbe-compose.ts` に「**PBEのスキル変更（データマイナー情報・未確定）**」セクションを追加:
  - 各 `PbeSourceTweet` を、有効なtweet status URLなら**公式oEmbed埋め込み**（既存 `embed.ts` の `isValidTweetStatusUrl`・G7/E22の embed ブロックを流用）、そうでなければ**短い引用（逐語text）＋画像（mediaUrls）＋出典（作者ハンドル・tweet URL）**で表示。
  - セクション冒頭に注記:「以下はデータマイナー（Spideraxe氏）およびRiot開発陣のPBE投稿に基づく**未確定情報**です。数値は本番リリース時に変更される場合があります。正式な数値は公式パッチノートで確定します。」
  - 件数上限（env `PBE_X_MAX_TWEETS`、既定 6 等）。**moderation を必ず通す**（NG語・個人攻撃除去）。
  - 逐語維持（ツイートtextそのまま・数値をこちらで作らない）。画像はホットリンク＋出典明記。
- CDragonの確定的な数値（アイテム・基本・cost/cd）と、Xの未確定スキル数値（埋め込み）は**視覚的に区別**（Xセクションは「未確定・出典付き」を明示）。

### F-PBE5-3: 人手キュレーション枠（半自動・任意・ファイルベース）
- 画像内の数値など自動で拾えない分を、**人が手で書き起こせる任意のキュレーションファイル**（例 `data/pbe-curation.json`、gitignore可・VPSで編集）を読み込み、存在すれば PBE記事の該当セクションに**人手記載（逐語・出典明記）**として差し込む。無ければ何もしない。
  - 形式は最小（`{ patch: "26.16", notes: [{ champion, skill, text, source }] }` 等）。捏造しない（人が公式/Spideraxe氏の投稿を見て転記する前提の枠）。
  - 管理UIは作らない（ファイル編集で足りる・半自動の現実解）。

### F-PBE5-4: タイトル・鮮度
- PBE記事タイトルに「スキル変更を含む」ことが分かる鮮度（既存の「【PBE先行】…（随時更新）」の範囲で・AI不使用）。

## 制約・非目標
- **AIは使わない**（統合・注記・キュレーション差し込みは純ルール）。**逐語維持・捏造禁止**（ツイート・キュレーションは逐語・数値をこちらで作らない・OCRしない）。
- **opt-in厳守**: `PBE_ARTICLE_MODE` off/未設定で完全同一（回帰ゼロ）。`X_API_KEY` 未設定ならXセクションは出さず**CDragon自動分のみ**（$0）。
- **コスト安全設計必須**: X取得は「PBE窓＋キーあり＋レート制限内」のみ。毎パイプライン・毎実行で叩かない。
- 著作権: ツイートは**転載でなく埋め込み/短い引用＋出典**（主従・出典明記）。画像ホットリンク＋出典。個人攻撃・晒しは moderation で除去。
- **DBスキーマ変更なし・新規npm依存なし**。CDragon/公式ノート経路(S1/S2/S4/S5)・G7 X反応記事は不変。

## テスト（必須・実HTTPを叩かない・fixtureモック）
1. opt-in無効（既定）で回帰ゼロ。`X_API_KEY`未設定ならXセクションを出さずCDragon自動分のみのPBE記事になる（X取得を呼ばない）。
2. `on`＋キーあり＋pbe≠latест＋レート内のとき、PbeSourceTweet（fixture）がPBE記事に「未確定・出典付き」セクションとして埋め込み/引用される（逐語text＋画像＋作者＋URL）。moderationを通る。
3. レート制限: 前回取得から間隔内なら再取得しない（X課金抑制）。
4. 人手キュレーションファイルがあれば逐語で差し込まれ、無ければ何もしない。
5. スキル数値をこちらで機械生成/OCRしていない（ツイート逐語・埋め込みのみ）ことの担保。
6. 既存の pbe-article/pbe-compose/G7 X/収集/生成テストが回帰しない。

## 受け入れ基準
1. `npx vitest run` 全Green・`tsc`・`build`・`lint` 通過。
2. `PBE_ARTICLE_MODE=on`＋`X_API_KEY`設定＋pbe≠latest で、PBE記事に CDragon確定分＋**Spideraxe/Phroxzon のツイート埋め込み（未確定・出典付きのスキル数値）**が出る。off/キー無しでは CDragon のみ・追加コスト0。
3. AI不使用・逐語維持・捏造なし（未確定・出典明示）・コスト安全設計（PBE窓＋キー＋レート制限）・DBスキーマ変更なし・新規依存なし・既存経路不変。

## 評価基準（evaluator向け）
- テスト全Green・build/tsc/lint通過・コンソールエラー0。
- opt-in無効/キー無しで回帰ゼロ（CDragonのみ・$0）。有効時にツイート埋め込み（未確定・出典・逐語・画像）がPBE記事に統合され、moderationを通る。レート制限でX課金が抑制される。人手キュレーション枠が機能する。
- 受け入れ基準1〜3を満たす。
