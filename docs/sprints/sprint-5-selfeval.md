# Sprint 5 自己評価レポート

## 実装した内容
- `src/lib/generation/title.ts`（新規）: 煽り速報タイトル生成(F8)。LLM非依存の決定論ロジック。
  - `LABELS`（速報/悲報/朗報/朗報か？/議論/海外の反応）、`HOOKS`（10種の感情フック語尾）、`HOOK_PATTERNS`（チェッカー用正規表現）を定義。
  - `extractConcreteElements(sourceText)`: パッチ番号→チャンピオン名(約130語・日英併記)→大会名(Worlds/MSI/LCK等)→バージョン番号→数値+単位→汎用カタカナ固有名詞(ストップリストで一般語彙を除外)→裸の数値、の優先順で `sourceText` の**部分文字列そのもの**を返す(捏造防止)。
  - `generateHookTitle(input)`: ラベル・フックはハッシュシード(内容依存)で選択→バリエーションを担保。主語(具体要素 or フォールバック)+本文由来の文脈(不足時は安全なフィラーで補完、切り詰め時は既存の `gistOf` と同じ慣習で「…」を付与)+フックを組み立て、全角相当20〜48文字に収める(超過/不足のガードロジック込み)。
  - `checkTitleQuality(title, sourceText)`: ラベル有無/具体要素有無/感情フック合致/文字数範囲の4点を判定し `passed` を返す。
  - 安全フィルタ: NGワード(差別的・攻撃的な語)のブロックリストで本文由来の抽出テキストをサニタイズ。
- `src/lib/generation/generate-article.ts`: `generateArticleForCandidate` が仮タイトル(`candidate.title`)ではなく `generateHookTitle` の生成結果を記事タイトルとして使うよう差し替え。
- `src/lib/generation/pipeline.ts`: 既存記事へのタイトル再適用手段として `regenerateArticleTitle`（1件）/ `regenerateAllArticleTitles`（全件、失敗しても他記事の処理は継続）を追加。生成元の `CollectedItem` が残っていればその原題+本文を、なければ記事の現タイトル+本文テキストをソースにする。
- `scripts/regenerate-titles.ts`（新規）+ `package.json` に `regenerate-titles` スクリプト追加。
- `src/lib/__tests__/generation-title.test.ts`（新規、13件）: チェッカーの合格例・不合格例(ラベル欠如/具体要素欠如/感情フック欠如/文字数不足の4パターン個別)、`extractConcreteElements`の非捏造性、生成タイトルのラベル/具体要素/感情フック/文字数/安全フィルタ、10件サンプルのベンチマーク合格率、バリエーション確認。

## 技術選定
- 新規ライブラリ追加なし。既存の純関数+Vitestの方針、`text-utils.ts`（`gistOf`の「…」切り詰め慣習）を踏襲。
- チャンピオン名・大会名の語彙リストはハードコード（外部辞書API等は導入せず、architecture.md方針通りモック/ルールベースで完結）。

## 受け入れ基準チェック（自己申告）
- [x] 記事本文（原題+本文）を入力すると、まとめ速報型タイトルが1本生成される — `generateHookTitle` で実装、テストで確認。
- [x] 冒頭に定義済みラベル語彙のいずれか1つを【】付きで含む — 全生成タイトルで確認（テスト・実データとも）。
- [x] 記事内容に実在する具体要素を最低1つ含み、本文に存在しない固有名詞を捏造しない — `extractConcreteElements`が`sourceText`の部分文字列のみを返す設計。テストで「抽出要素は全てsourceTextの部分文字列」を検証済み。
- [x] 定義済み感情フックパターンのいずれかに合致する — 生成タイトルは必ず`HOOKS`のいずれかで終わり、対応する`HOOK_PATTERNS`にマッチ。
- [x] 文字数が全角20〜48文字相当に収まる — 10サンプル全件で20〜24文字相当（実測、下記参照）。ガードロジックで範囲外を防止。
- [x] タイトル品質チェッカーが4点を判定し合格/不合格を返す — `checkTitleQuality`実装済み。
- [x] 10件サンプルでチェッカー合格率90%以上 — **実測 10/10 = 100%**（下記実行結果参照）。
- [x] 複数記事に対する生成でラベル・語尾が偏らない — 10サンプルで確認：ラベル6種類中5種類、フック10種類中8種類が出現（テストで`usedLabels.size>=2`・`usedHooks.size>=2`をアサート、実測はさらに良好）。
- [x] 差別的・攻撃的・個人中傷表現を含むタイトルが生成されない — ラベル/フック語彙自体が安全語のみで構成。本文由来の抽出テキストにはNGワードサニタイズを適用。NGワード混入本文からの生成でNGワードが含まれないことをテストで確認。
- [x] 生成タイトルがSprint1・2の記事カード・個別記事ページのタイトルとして表示されレイアウトが崩れない — `next build`→`next start`で実際に生成・確認（下記参照）。`break-words`クラスにより折り返し、崩れなし。

## アプリの起動方法
- 依存インストール: `npm install`（既存プロジェクト、追加パッケージなし）
- DBシード: `npm run db:seed`
- 収集→生成（実データでタイトル生成を確認する場合）: `npm run collect` → `npm run generate`
- 既存記事へのタイトル再適用: `npm run regenerate-titles`
- 開発起動: `npm run dev`（http://localhost:3000）
- 本番相当起動: `npm run build` → `npm run start`（既定 http://localhost:3000。自己確認時は `npm run start -- -p 3411` でポート指定）
- テスト: `npm test`（Vitest, 全97件）

## 既知の問題・懸念点
- 汎用カタカナ固有名詞フォールバック(`findGenericProperNoun`)はストップリスト方式のため、稀に一般語(未登録の語)を「具体要素」として誤検出する可能性がある。10サンプルではチャンピオン名/パッチ番号/大会名の優先抽出で問題なく100%合格を確認済みだが、将来ランダムな実データ全件では合格率が90%を下回るケースがありうる（brief上は10サンプルでの90%以上が基準のため、現状は充足）。
- 生成タイトルの文脈部分（フック直前の本文引用）は本文の先頭から機械的に切り出すため、日本語として完全に自然な一文になるとは限らない（「…」で省略を明示する形で対応、既存の`gistOf`と同じ慣習）。中核差別化機能としての「読みたくなる自然さ」は今後LLM本接続（Sprint方針上は将来課題）でさらに改善余地あり。
- `/security-review`・`/code-review`はローカル専用パイプラインの制約上generatorからは自動実行できない（`reference/learnings.md`記載の既知の制約。オーケストレーター側の手動レビューで代替される想定）。

## 10件サンプルの実測結果（合格率とタイトル実例）
`npx vitest run` 内のベンチマークテストで使用した10件サンプル（Reddit/5ch/Riot公式風の内容を模した架空記事化候補）に対する実測:

```
PASS RATE: 10/10 = 100.0%
```

生成タイトル実例（サンプル文脈+チェッカー判定を全項目確認済み、長さは全角相当）:
- 【朗報か？】パッチ14.6、本パッチでは…に賛否両論（24文字相当）
- 【議論】ヤスオ、海外サイトの情…、まさかの展開に（24文字相当）
- 【悲報】Worlds、本日行われた準決勝の結…だった件（24文字相当）
- 【速報】セラフィン、スレッドで…がヤバいと話題に（24文字相当）
- 【速報】ゼド、直近のランクデータでは、…で大荒れ（24文字相当）
- 【朗報か？】LEC、有名実況者がLEC決勝の…が話題に（24文字相当）

実データ（`npm run collect`→`npm run generate`で実際にRiot/Reddit/5chモックフィクスチャから生成）でも動作確認:
- 【海外の反応】ヤスオ、壁飛び5連続…、ついに判明
- 【朗報】Yasuo、Clip of an incr…がヤバいと話題に（英語Reddit文脈でも"Yasuo"を具体要素として抽出できることを確認）
- 【朗報か？】Worlds、The group stage …に賛否両論
- 【速報】14.6、Riot pushed a big jungle…で大荒れ

既存記事(シードデータ、生成元CollectedItem無し)への再適用（`npm run regenerate-titles`、フォールバックで記事title+本文テキストをソースに使用）:
- 旧: "【悲報】パッチ14.6でジャングル大幅弱体化、海外勢が阿鼻叫喚してる件" → 新: "【議論】パッチ14.6、パッチ14.6の変…を巡り議論に"
