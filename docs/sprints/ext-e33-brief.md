# 拡張E33 — 2レス以上の反応記事は必ず一部を色付き強調（全黒字記事の解消）

運用フィードバック起点。E32の色分け強調の上に、最低限の色保証を足す。対象: Web。

## 背景（なぜ）
- E25/E28/E32でLLMが「強調レス＋色」を選ぶが、LLMが強調ゼロと判断すると**色が全く付かない全黒字の記事**が出る。
- 要望: **1記事に反応レスが2つ以上あるなら、必ず一部を色付き強調**にして、全黒字を無くす。

## 含まれる機能

### F-E33-1: 色付き強調の最低保証（決定論フォールバック）
- `src/lib/generation/compose.ts` の `buildReactionBlocks`（反応ブロック配列を作った後）で:
  - 反応ブロックが **2件以上** かつ **1件も強調(`emphasis`/`emphasisColor`)が付いていない** 場合のみ、決定論的に色付き強調を補う。
  - 補う件数: `minColored = Math.max(1, Math.round(blockCount / 4))`（例 2〜6件→1、7〜10件→2 …）。
  - 対象レス: **本文の総文字数が長いレスを優先**で `minColored` 件選ぶ（同点は元の並び順＝index昇順で安定・決定論的）。
  - 色: `["red","blue","green"]` を順番に割り当てて彩りを出す。選んだレスに `emphasis:true` ＋ `emphasisColor` を付与。
  - **LLMが1件でも強調を付けている記事には手を出さない**（LLMの編集判断を尊重。全黒字のときだけ補う）。
- この保証は LLM選定時（強調ゼロ）・mock/フォールバック時（全レス・強調なし）のどちらにも効く＝実データでもmockでも全黒字が無くなる。

## 制約・非目標
- 逐語転載を維持（付けるのは表示上の強調色のみ。本文・行・レス選定は変えない）。
- 1レスのみの記事には強制しない（2件以上のみ）。riot/clip記事・タイトル・サムネ・NG処理には触れない。
- LLM呼び出しは増やさない（決定論の後処理のみ）。新規依存なし。
- 行単位の red/orange 強調・レス単位の色(E32)の描画は変更しない（既存の描画をそのまま使う）。

## テスト（必須）
1. 反応レス2件以上・強調ゼロの記事に、決定論的に `minColored` 件の色付き強調（`emphasis:true`＋`emphasisColor`）が付く。長いレス優先・色は red→blue→green の順で安定。
2. 既にいずれかのレスに強調が付いている記事は変更されない（LLM選定を尊重）。
3. 反応レス1件の記事には色を強制しない。
4. mock既定（強調なし）でも2件以上なら色が付く（＝全黒字にならない）。決定論で毎回同じ結果。
5. 逐語（本文テキスト）は不変。既存のE25/E28/E32/E27テストの本旨（選定・行抽出・伏字・色）に矛盾しないよう、mockで強調なしを前提にしていた既存アサーションは本仕様に合わせて更新（色が付くこと自体は本スプリントの意図）。

## 受け入れ基準
1. `npx vitest run` 全Green（新規＋更新含む）。
2. `npx tsc --noEmit`・`npm run build`・`npm run lint` 通過。
3. 反応レス2件以上の記事は必ず一部が色付き強調になる（LLM/mock問わず）。全黒字の反応記事が出ない。
4. 逐語維持・新規依存なし・LLM呼び出し増なし。

## 評価基準（evaluator向け）
- テストGreen・build/tsc/lint通過。実機(mock)でトップ/反応記事がコンソールエラー0で表示され、2件以上のレスを持つ記事に色付き強調が視認できる（全黒字が無い）。
- 受け入れ基準1〜4を満たす。
