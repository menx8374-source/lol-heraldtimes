# 拡張スプリント E13: リアクションを1ユーザー1回に制限（記事の絵文字・コメントの賛否）

対象プラットフォーム: web（既存アーキテクチャに従う）

## 背景
現状、記事の絵文字リアクション（😂😮😡👍）とコメントの賛否（👍Good/👎Bad）は、連打抑止のみで
同一ユーザーが何度でも加算できる。参考サイト同様、**1ユーザー（＝1ブラウザ）につき1回まで**に制限し、
票の水増しを防ぐ。

## 前提
ログイン機能は無い方針のため、ユーザー識別は**ブラウザのlocalStorage**で行う（サーバー側の完全な
本人性保証はしない＝参考まとめサイトと同様の緩い制限。目的は正当な閲覧者による多重加算の抑止）。

## 含まれる機能

### F-E13-1: 記事の絵文字リアクションを1記事につき1つ・1回に
- 1記事につき、ユーザーが有効にできる絵文字リアクションは**同時に1つだけ**。
  - 未選択の絵文字を押す → その絵文字を+1し、自分の選択として記録。
  - 既に選択中の絵文字をもう一度押す → 取り消し（-1）して未選択に戻す（トグル）。
  - 別の絵文字を押す → 前の選択を-1、新しい絵文字を+1（切替）。
- 自分が選択中の絵文字はUI上で「選択済み」と分かるハイライトにする。リロード後も選択状態が保持される（localStorage）。
- 結果として、1ユーザーの寄与はどの記事でも常に最大1票。

### F-E13-2: コメント/返信の賛否（👍/👎）を1コメントにつき1つ・1回に
- 1コメント（返信含む）につき、ユーザーが有効にできる投票は**👍か👎のどちらか1つだけ**。
  - 未投票で👍or👎を押す → その票を+1し記録。
  - 同じ票をもう一度押す → 取り消し（-1）。
  - もう片方を押す → 前の票を-1、新しい票を+1（切替）。
- 自分の投票はUI上で分かるハイライトにする。リロード後も保持（localStorage）。

## データ層・API（サーバー）
- リアクション/投票のエンドポイントを、**加算だけでなく減算（取り消し・切替）にも対応**させる。
  - 記事リアクション `POST /api/articles/[slug]/reactions`: 例 `{ emoji, op: "add" | "remove" }`。remove は該当カウントを**0未満にしない**（floorガード）。
  - コメント投票 `POST /api/articles/[slug]/comments/[number]/vote`: 例 `{ type, op: "add" | "remove" }`。同様に0未満にしない。
  - 切替はクライアントが「旧票をremove → 新票をadd」の2リクエスト、または1リクエストで旧新を受け取る形のどちらでもよい（実装が単純な方で可）。
- 公開限定（`PUBLISHED_ONLY`）・存在しない/held の記事/コメントへの操作は従来どおり弾く。減算でカウントが負にならないことをテストで担保。
- 既存の集計・整形（`mergeReactionCounts` 等）は流用。

## クライアント（localStorage）
- localStorage のキーは記事slug・コメント番号でスコープする（例: `reaction:<slug>` に選択中の絵文字、`vote:<slug>:<number>` に good|bad）。
- 楽観的更新は維持しつつ、サーバーの返却カウントで上書きする。二重送信抑止（pending）も維持。
- localStorage 非対応・プライベートモード等で読み書きに失敗しても、UIをブロックせず動作する（フォールバック: その場限りの選択状態）。

## 実装方針
- localStorage の読み書き・「今の選択→クリックした対象」から次アクション（add/remove/switch）を決めるロジックは、
  可能な限り純関数に切り出して単体テストする（localStorageアクセスは薄いラッパにし、純粋な状態遷移をテスト）。
- 記事リアクション（`reaction-buttons.tsx`）とコメント投票（`comment-vote-buttons.tsx`）で、選択状態管理・トグル/切替の
  仕組みが重複するなら共通フック/ヘルパに寄せる（ただしE13差分内に閉じる範囲で）。
- シークレットのハードコード禁止。新規依存は追加しない。

## 受け入れ基準（検証可能・原文）
- [ ] 記事で同じ絵文字を2回押しても、合計は+1のまま（2回目で取り消され0に戻る＝トグル）。連打で複数加算されない。
- [ ] 記事で別の絵文字を押すと、前の絵文字が-1され新しい絵文字が+1される（同時に有効なのは1つ）。
- [ ] コメントで👍を押した後に👎を押すと、👍が-1・👎が+1される（どちらか1つ）。同じ票の2度押しで取り消し。
- [ ] 自分の選択/投票がUIでハイライトされ、リロード後も保持される。
- [ ] 減算でカウントが負の値にならない（0で下げ止まる）。
- [ ] 公開限定・存在しない/held への操作は従来どおり弾かれる（不正POSTで確認可能）。
- [ ] localStorage が使えない環境でもエラーで画面が壊れない。
- [ ] `npm test` が全てGreen（add/remove/switch の状態遷移、減算の0フロア、APIの op 分岐にテストを追加）。

## 評価基準（evaluator向け）
- 致命的バグ0件／コンソール・実行エラー0件／上記受け入れ基準の充足率100%／テストGreen。1つでも下回れば全体FAIL。
- Playwright MCP で、記事絵文字の1回制限・トグル・切替、コメント👍/👎の1回制限・切替、リロード後の保持、負値にならないことを確認。プレビュー画像を保存すること。
