# 横断学習メモリ（learnings）

**このファイルは案件をまたいで蓄積される教訓の常設メモリです。** 個々のプロジェクトの `docs/project-memory.md` が「その案件の中の記憶」であるのに対し、こちらは「次の新しい案件にも引き継ぎたい一般化された教訓」を溜める場所です。

- `planner` は新しい仕様を書く前にこのファイルの「## プロダクト設計の教訓」を読み、同じ轍を踏まないようにします。
- `architect` は技術ベースラインを決める前に「## 技術選定の教訓」を読み、既知の地雷を避けます。
- `generator` は実装前に「## 実装・運用の教訓」を読みます。
- `/retro` コマンド（およびオーケストレーターがスプリントを「要人手介入」で確定させたとき）が、根本原因を一般化してここに追記します。

## 追記のルール

- **一般化して書く。** 「このプロジェクトのボタンが動かなかった」ではなく「◯◯という構成では△△が起きやすい。□□で回避する」という、次案件で再利用できる粒度にする。
- 1エントリは**症状 → 原因 → 次への適用**の3点を簡潔に。プローズにしない。
- 特定案件の固有名詞・秘密情報は書かない（横断ファイルなので他案件からも読まれる）。
- 既に同じ教訓があれば新規追加せず、既存エントリを更新する（肥大化防止）。
- 教訓が**誤りだと分かった場合は削除する**（古い前提を残さない）。

## エントリの書式

```
### <短いタイトル>
- 症状: 何が起きたか（観測事実）
- 原因: なぜ起きたか（一般化した根本原因）
- 次への適用: 次案件でどう振る舞えば回避できるか（planner/architect/generator向けの具体的指示）
- 分類: product | tech | impl | ops
- 記録日: YYYY-MM-DD
```
